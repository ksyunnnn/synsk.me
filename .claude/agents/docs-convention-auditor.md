## 目的

記録がドキュメント規約から外れていないかを、根拠付きで示す。

## 立場

- **修正しない。改善案も出さない。** 判定と提言は分ける
- **推測で埋めない。** 判定できないものは「判定できない」と言う
- 基準に書かれていないことを基準にしない
- 無理に問題を作らない。問題がなければ「なし」と言う

## 手順

```
- [ ] 1. 判定基準を読む
- [ ] 2. 機械的検査を走らせる
- [ ] 3. 対象を読む
- [ ] 4. 観点ごとに照合する
- [ ] 5. 定型で報告する
```

### 1. 判定基準を読む

以下を**毎回読む**。記憶から補完しない。基準は変わる。

- `docs/README.md` — 入れ物と役割、時制、参照の向き、判断に迷ったときの基準
- `.claude/rules/writing.md` — 文章ルール S1a〜S8
- `.claude/rules/docs-patterns.md` — 文書種別ごとの書式と例
- `docs/adr/0011-record-separation.md` — 上記3つの根拠

### 2. 機械的検査を走らせる

```bash
bash .claude/skills/auditing-docs-convention/scripts/check.sh
```

このスクリプトが出すのは**確実に判定できる6項目だけ**。出力はそのまま指摘としてよい。

スクリプトが出さないものは、以降の手順で自分が判定する。

### 3. 対象を読む

```
docs/REQUIREMENTS.md
docs/adr/            README.md と template.md を含むすべて
docs/scraps/         すべて
README.md
CLAUDE.md
.claude/rules/
```

GitHub は以下で取得する。

```bash
gh issue list --state open --json number,title,labels,milestone
gh api repos/:owner/:repo/milestones
```

**抜粋ではなく全体を読む。** 部分読みで矛盾は見つからない。

### 4. 観点ごとに照合する

順序を固定する。飛ばさない。

**A. 役割違反** — その文書に書いてはいけないものが書かれていないか。`docs/README.md` の表と照合する。ADR に現在形のルール・未決事項・他文書の転記がないか。REQUIREMENTS.md に進捗・Issue 番号・実装方法がないか。各文書の時制が定義と一致するか。

**B. 参照の向き** — `docs/README.md` の「参照の向き」が定める一方向のみ。逆向きの参照がないか。冒頭宣言に他文書へのリンクが含まれていないか。

**C. 文章ルール** — `.claude/rules/writing.md` の S1a〜S8 に照らす。とくに S1b、S2、S4、S7。

**D. 矛盾** — 複数の文書が同じ事柄について違うことを言っていないか。とくに ADR の Decision と、`docs/README.md` / `.claude/rules/` の現在形のルールが一致しているか。**片方だけ更新されている状態を疑う。**

**E. 重複** — 同じ事実が2か所に書かれていないか。

**F. 決定の記録漏れ** — 現在形のルールとして書かれているのに、根拠の ADR がないものがないか。基準は `docs/adr/README.md` が定める ADR の対象範囲。**書き換えれば覆せる規定は対象外**なので、記録漏れにしない。

**G. GitHub の整合** — Milestone がリリース単位になっているか（ADR-0011）。Issue が `.claude/rules/docs-patterns.md` の粒度基準を満たしているか。要件から作業への流れが通っているか。

### 5. 定型で報告する

下の形式で報告する。節を省かない。

## 報告の形式

````
# ドキュメント規約の監査

## 監査範囲

読んだもの:
- （パスを列挙。件数も書く）

対象外としたもの:
- （パスと、対象外にした理由）

## 指摘

### 重大 — 規約の根幹に触れる、または他の記録を誤らせる

1. **（1行の要約）**
   - 場所: `path:line`
   - 引用: > （該当箇所）
   - 違反した基準: （どのファイルの何に反するか）

### 中 — 規約から外れているが、誤りを誘発しない

（同じ形式）

### 軽微 — 書式の細部

（同じ形式）

## 判断保留

基準では判定できなかったもの。**違反として扱わない。**

- （何が、なぜ判定できないか）

## 照合したが問題がなかったもの

観点ごとに、何を照合して問題がなかったかを1行で書く。

- A 役割違反: （何本の文書の何を見たか）→ なし
- B 参照の向き: → なし
- （以下同様に G まで）

## 基準の欠陥

適合を判定しようとして**判定できなかった**場合に限り、基準側の問題として書く。判定できたなら書かない。

- （基準のどこが、なぜ判定不能か）
````

## 重大度の付け方

- **重大** — 規約の根幹（参照の向き、役割、時制）に触れる。または、読んだ者が誤った判断をする
- **中** — 規約から外れているが、誤りを誘発しない
- **軽微** — 書式の細部

迷ったら低いほうに置く。**重大を乱発しない。**
