# ドキュメントの書き方

役割と時制の定義は [docs/README.md](../../docs/README.md) にある。ここは書式の例だけを持つ。

## 冒頭の宣言

`adr/` `REQUIREMENTS.md` `research/` `notes/` の各文書は、**見出しの直後**に引用ブロックで宣言を置く。他文書へのリンクを含めない（参照の向きに違反するため）。

```
adr/:             > この文書は決定を記録する。有効な要件は持たない。
REQUIREMENTS.md:  > この文書は満たすべきことだけを書く。進捗と実装方法は書かない。
research/:        > この文書は調査した時点の記録。決定は持たない。
notes/:           > 予告なく削除される。他文書から参照しない。
```

`VISION.md` `PRINCIPLES.md` `template.md` と各ディレクトリの `README.md` は宣言の対象外。ただし `notes/README.md` は、その場所の性質を読む人に伝える必要があるため宣言を持つ。

## 要件

書式は見出し1行と根拠1行の2行だけ。ID は通し番号で、領域で分けない。決定日は書かない（根拠 ADR が持つ）。

```
✓ ## FR-10: internal コンテンツの過去の版を保持し、任意の版に戻せる
  根拠: ADR-0010

✗ ## FR-10: 記事の版管理ができる
   → 何ができれば満たされるか読めない

✗ ## FR-09: 再取得に配慮する
   → 検証できない

✗ ## NFR-01: バックアップを適切に行う
   → 「適切」が判定できない
```

FR は機能要件、NFR は非機能要件（性能・可用性・セキュリティ・保守性・コスト）。

対象を指す語は `activity` / `career` / `project` / `internal コンテンツ` の4つに固定する。「エントリ」「レコード」「記事」を使わない。

## ADR

対象は、**代替案があり、それを退けた決定**に限る。自明な判断、可逆で影響の小さい決定、文書を作るという宣言は ADR にしない。

単位は決定であって要件ではない。1つの決定から複数の要件が派生する。

```
✓ Decision: 外部プラットフォームへの転載は synsk.me を正本とする（POSSE）
✗ Decision: VISION.md と PRINCIPLES.md を定義する
   → 代替案がない。文書の存在告知でしかない

✓ Context: Medium の RSS には rel="canonical" が含まれない（2026-08-20 に実フィードを取得して確認）
✗ Implementation Notes: 配信データに `tags` を含めてはならない
   → 現在形のルール。要件文書が持つべき

✓ Context: 詳細は content-model-design.md を参照
✗ Context: （content-model-design.md の表をそのまま転記）
   → 転記の過程で未決が決定に格上げされる
```

`Implementation Notes` に決定でないものを書かない。未決事項の節を作らない。未決は `question` ラベルの Issue が持つ。

`Deciders` は `synsk` と書く。

## Issue

要件本文を再掲しない。ID で参照する。

```
✓ 要件: FR-10
  ## 完了条件
  - 過去の版が一覧できる
  - 任意の版に戻せる

✗ ## 概要
  記事の版管理ができるようにする。過去の版を保持し…
   → 要件文書のコピー。要件が変わると嘘になる
```

## research

調査した時点の記録。書き換えない。ADR から参照されないものは `notes/` へ置く。
