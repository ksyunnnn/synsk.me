# Feature Specification: note を書いて公開し、読む

**Feature Branch**: `feature/note-write-and-read`

**Created**: 2026-09-17

**Status**: Draft

**Input**: User description: "作り手が /dash/ で note を新しく作り、題・本文・識別子を書いて保存し、公開する。公開した note は、訪問者が /notes/{slug} で題と本文を読める。作り手は note を書き換えることと、完全に削除することができる。下書きの note は訪問者に見えない。作り手以外は /dash/ に入れない。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - note を書いて公開し、訪問者が読む (Priority: P1)

作り手が `/dash` で note を新しく作り、題・本文・slug を書いて保存し、公開する。訪問者は `/notes/{slug}` でその note の題・公開日・本文を読む。

**Why this priority**: 書いたものが訪問者に届く経路が通らなければ、note は存在しないのと同じである。書き換えと削除は、この経路の上に載る。

**Independent Test**: `/dash` で note を1件作って公開し、作り手としてログインしていないブラウザで `/notes/{slug}` を開くと、題・公開日・本文が読める。

**Acceptance Scenarios**:

1. **Given** 作り手が `/dash` を開いている、**When** 題・本文・slug を入力して保存する、**Then** 下書きの note が1件でき、`/dash` の note の一覧に下書きとして並ぶ
2. **Given** 下書きの note がある、**When** 訪問者が `/notes/{slug}` を開く、**Then** note がないことが伝わる表示になる
3. **Given** 下書きの note がある、**When** 作り手が公開する、**Then** 訪問者が `/notes/{slug}` で題・公開日・本文を読める
4. **Given** 作り手以外の人、**When** 本番またはプレビュー URL の `/dash` 配下のどの画面を開こうとしても、**Then** 画面は表示されず、note の作成・保存・公開・削除のどの操作もできない

---

### User Story 2 - 作り手が note を書き換える (Priority: P2)

作り手が、下書きの note や公開済みの note の題と本文を書き換える。

**Why this priority**: 公開した後に誤りを直せないと、誤った内容が訪問者に見え続ける。ただし書き換えがなくても、書いて届ける経路は成り立つ。

**Independent Test**: 公開済みの note の題を書き換えて公開し直し、`/notes/{slug}` に書き換えた題が出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 下書きの note がある、**When** 作り手が題と本文を書き換えて保存する、**Then** 書き換えた内容が保存される
2. **Given** 公開済みの note がある、**When** 作り手が題と本文を書き換えて保存する、**Then** 訪問者の `/notes/{slug}` には書き換える前の内容が出たままであり、作り手の画面では公開し直していない書き換えがあることが分かる
3. **Given** 公開済みの note を書き換えて保存した、**When** 作り手が公開し直す、**Then** 訪問者の `/notes/{slug}` に書き換えた内容が出て、公開日は変わらない

---

### User Story 3 - 作り手が note を削除し、戻す (Priority: P3)

作り手が、下書きまたは公開済みの note を削除する。削除した note は訪問者に見えなくなるが、データは残り、作り手が戻せる。

**Why this priority**: 出すべきでなかったものを消せないと、訪問者に見え続ける。書いて届ける経路と書き換えがあれば、削除がなくても日々の執筆は成り立つ。誤って削除したものを戻せないと、書いた内容を失う。

**Independent Test**: 公開済みの note を削除し、`/notes/{slug}` で note がないことが伝わる表示になり、`/dash` の note の一覧から外れることを確かめる。続けてその note を戻し、`/notes/{slug}` で削除する前と同じ題・公開日・本文が読めることを確かめる。

**Acceptance Scenarios**:

1. **Given** 公開済みの note がある、**When** 作り手が削除を選ぶ、**Then** 削除してよいかの確認を求められ、確認するまで削除されない
2. **Given** 削除の確認を求められている、**When** 作り手が確認する、**Then** 訪問者が `/notes/{slug}` を開くと note がないことが伝わる表示になり、作り手の画面では note の一覧から外れて、削除した note の一覧に並ぶ
3. **Given** note を削除した、**When** 作り手が同じ slug で note を新しく作ろうとする、**Then** その slug が使えないことが分かる
4. **Given** 公開済みの note を削除した、**When** 作り手がその note を公開で戻す、**Then** note の一覧に公開の状態で戻り、訪問者が `/notes/{slug}` で削除する前と同じ題・公開日・本文を読める
5. **Given** 公開済みの note を削除した、**When** 作り手がその note を下書きで戻す、**Then** note の一覧に下書きの状態で戻り、訪問者が `/notes/{slug}` を開くと note がないことが伝わる表示になる。続けて作り手が公開し直すと、公開日は削除する前と同じである
6. **Given** 一度も公開していない note を削除した、**When** 作り手がその note を戻す、**Then** 下書きで戻すことだけを選べ、note の一覧に下書きの状態で戻り、題と本文は削除する前と変わらない

---

### Edge Cases

- slug を入力せずに保存しようとしたとき、slug が足りないことが分かり、入力した題と本文は失われない
- 小文字の英字・数字・ハイフン以外を含む slug や、100文字を超える slug を入力したとき、使えないことが分かり、入力した題と本文は失われない
- 他の note が使っている slug を入力したとき、その slug が使えないことが分かり、入力した題と本文は失われない
- 題が空のまま公開しようとしたとき、公開されず、題が足りないことが分かる
- 題が200文字、本文が100,000文字を超えたとき、保存されず、どちらが長すぎるかが分かり、入力した題と本文は失われない
- 存在しない slug で `/notes/{slug}` を開いたとき、note がないことが伝わる表示になる
- 保存の途中で失敗したとき、保存に失敗したことが分かり、公開済みの内容は変わらない
- 別の画面で削除した note を保存・公開しようとしたとき、保存も公開もされず、note が存在しないことが分かる
- 削除した note の編集の画面を開こうとしたとき、note が存在しないことが分かる
- 別の画面で戻した note をもう一度戻そうとしたとき、何も書き込まれない
- 題と本文を変えずに保存したとき、版は増えない
- 削除した note が1件もないとき、削除した note の一覧は空であることが分かる
- 作り手のログインが切れた状態でフォームを送ったとき、何も書き込まれない。入力した題と本文は残らない
- note が1件もないとき、`/dash` の一覧は空であることが分かる
- note を読み出せなかったとき、訪問者の画面も作り手の画面も、読み出せなかったことが伝わる表示になる

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 作り手は `/dash` 配下で、題・本文・slug を入力して note を作れる
- **FR-002**: note は「下書き」と「公開」のどちらかの状態を持つ。作られた note は下書きである
- **FR-003**: 作り手は下書きの note を公開できる
- **FR-004**: 訪問者は、公開された note の題・公開日・本文を `/notes/{slug}` で読める。公開日は、その note を初めて公開した日を、日本時間（Asia/Tokyo）の日付で表す
- **FR-005**: 下書きの note と削除した note の題と本文は、訪問者に返すどの応答（本文、ページのメタデータ、エラーの表示）にも現れない
- **FR-006**: slug は小文字の英字・数字・ハイフンだけからなる1〜100文字で、削除した note を含むすべての note の間で重ならない
- **FR-007**: slug は、note を一度公開した後は変えられない
- **FR-008**: 作り手は note の題と本文を書き換えられる。公開済みの note を書き換えた内容は、作り手が公開し直すまで訪問者に見えない
- **FR-009**: 作り手は note を削除できる。削除は、作り手が確認してから行う。削除した note は訪問者に見えなくなり、題と本文の版・状態・初めて公開した日時はデータとして残る
- **FR-010**: 作り手以外は、本番とプレビュー URL のどちらでも、`/dash` 配下の画面を表示できず、note を作成・保存・公開・削除する操作と、削除した note を戻す操作を行えない。作り手の操作は、synsk.me の画面から送られた要求だけを受け付け、別のサイトから送られた要求は受け付けない
- **FR-011**: 存在しない note・下書きの note・削除した note への `/notes/{slug}` の要求は、note がないことを訪問者に伝える。状態コード・表示・応答のヘッダのどれにも、三者を区別できる違いを見せない
- **FR-012**: 本文は装飾を持たない文章である。訪問者の画面では、作り手が入れた改行の位置で改行して表示する
- **FR-013**: 保存と公開に失敗したとき、作り手は失敗したことを知ることができ、入力した題と本文は失われない。削除と、削除した note を戻す操作に失敗したとき、作り手は失敗したことを知ることができる。作り手であることを確かめられないときの扱いは Edge Cases による
- **FR-014**: 作り手は `/dash` で、削除していないすべての note を、下書きか公開か、公開し直していない書き換えがあるかとともに一覧できる
- **FR-015**: 題は200文字まで、本文は100,000文字までとする。超える内容は保存しない
- **FR-016**: 公開・削除・削除した note を戻すことは、作り手の操作が終わった後の、訪問者の最初の要求から反映される（`docs/REQUIREMENTS.md` の FR-17 にあたる）
- **FR-017**: 作り手の操作（作成・保存・公開・削除・削除した note を戻す）は、幅 360px の画面でも、キーボードだけでも行える（`docs/REQUIREMENTS.md` の FR-16 にあたる）
- **FR-018**: 作り手は `/dash` 配下で、削除した note を一覧でき、削除してからの時間によらず戻せる。戻すとき、作り手は下書きで戻すか公開で戻すかを選ぶ。公開で戻せるのは、公開したことのある note だけである。公開で戻した note は、訪問者に削除する前と同じ題・本文・公開日を見せる。下書きで戻した note は訪問者に見えず、初めて公開した日時と最後に公開した題と本文を保つ。どちらで戻しても、作り手が書き換えている題と本文は削除する前と変わらない
- **FR-019**: 削除した note は、戻すまで書き換えも公開もできない
- **FR-020**: note を完全に消す操作を synsk.me の画面に置かない。完全に消すのは Cloudflare の管理画面から行う（`docs/REQUIREMENTS.md` の FR-11 にあたる）。削除した note のデータは残るため、削除は `docs/REQUIREMENTS.md` の NFR-01（永続化したデータ全体を復元できる）を妨げない
- **FR-021**: 保存と公開のたびに、その題と本文を note の版として残す。版は書き換えも削除もせず、数に上限を設けない。題と本文が直前の版と同じなら、版を足さない（`docs/REQUIREMENTS.md` の FR-10 のうち、過去の版を保持することにあたる）

### Key Entities

- **note**: 作り手が synsk.me で書いて公開する文章1件。slug・状態（下書き / 公開）・初めて公開した日時・最後に公開した版・削除した日時を持つ。削除した日時を持つ note が、削除した note である
- **版**: note の題と本文の1組。保存と公開のたびに残す。作り手が書き換えている内容は最新の版、訪問者に見せる内容は最後に公開した版である

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 作り手が `/dash` を開いてから、note を1件書いて公開し、訪問者の画面で読めるまでを、synsk.me の外の道具を使わずに行える
- **SC-002**: 作り手以外が、本番とプレビュー URL の `/dash` 配下の画面と操作に到達できる経路が0件である
- **SC-003**: 訪問者に返す応答に、下書きの note の題・本文が現れる件数が0件である
- **SC-004**: 公開した note の URL（`/notes/{slug}`）は、題と本文を書き換えても変わらない
- **SC-005**: 削除の操作が終わった後に訪問者に返す応答に、削除した note の題・本文が現れる件数が0件である
- **SC-006**: 削除した note を公開で戻した後、その note の状態・題・本文・公開日が、削除する前と一致する。下書きで戻して公開し直した後、公開日が削除する前と一致する
- **SC-007**: 存在しない note・下書きの note・削除した note への `/notes/{slug}` の応答の間で、状態コード・表示・応答のヘッダの名前と値（要求ごとに変わる値を除く）が一致する
- **SC-008**: 作り手が保存・公開した題と本文のうち、版としてデータに残っていないものが0件である

## Assumptions

- この spec が扱うのは、1件の note を書いて公開し、読むまでの経路だけである。`/notes` の一覧、題から slug の候補を出すこと、公開前に見た目を確かめること、画像は扱わない
- `docs/REQUIREMENTS.md` のうち、FR-10 の任意の版に戻すこと、FR-13（公開前の見た目の確認）、FR-14（保存操作なしの保持）、FR-15（URL から参照先の情報を出す）は扱わない
- 公開済みの note を下書きに戻すのは、削除した note を下書きで戻すときだけである。公開中の note を直接下書きに戻す操作は扱わない
- note の見た目は扱わない。訪問者の画面も作り手の画面も、読めて操作できることだけを求める
- 作り手は1人である。複数の作り手が同じ note を同時に書き換える場合は扱わない
- 作り手以外を `/dash` に入れない仕組みは、`docs/decisions/0013-access-authentication.md` が定めるアプリケーションの外の仕組みと、`docs/decisions/0036-verify-access-jwt-in-app.md` が定めるアプリケーションの中の確認による
- note の保管先は `docs/decisions/0014-authoring-and-datastore.md` が定める。この spec は保管の形式を決めない
- slug を題と別に持つことは `docs/decisions/0016-url-conventions.md` による
