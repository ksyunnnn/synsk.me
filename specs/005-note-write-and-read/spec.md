# Feature Specification: note を書いて公開し、読む

**Feature Branch**: `feature/note-write-and-read`

**Created**: 2026-09-17

**Status**: Draft

**Input**: User description: "作り手が /dash/ で note を新しく作り、題・本文・識別子を書いて保存し、公開する。公開した note は、訪問者が /notes/{slug} で題と本文を読める。作り手は note を書き換えることと、完全に削除することができる。下書きの note は訪問者に見えない。作り手以外は /dash/ に入れない。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - note を書いて公開し、訪問者が読む (Priority: P1)

作り手が `/dash/` で note を新しく作り、題・本文・識別子を書いて保存し、公開する。訪問者は `/notes/{slug}` でその note の題と本文を読む。

**Why this priority**: 書いたものが訪問者に届く経路が通らなければ、note は存在しないのと同じである。書き換えと削除は、この経路の上に載る。

**Independent Test**: `/dash/` で note を1件作って公開し、作り手としてログインしていないブラウザで `/notes/{slug}` を開くと、題と本文が読める。

**Acceptance Scenarios**:

1. **Given** 作り手が `/dash/` を開いている、**When** 題・本文・識別子を入力して保存する、**Then** 下書きの note が1件できる
2. **Given** 下書きの note がある、**When** 訪問者が `/notes/{slug}` を開く、**Then** note がないことが伝わる表示になる
3. **Given** 下書きの note がある、**When** 作り手が公開する、**Then** 訪問者が `/notes/{slug}` で題と本文を読める
4. **Given** 作り手以外の人、**When** `/dash/` 配下のどの画面を開こうとしても、**Then** 画面は表示されず、note の作成・保存・公開・削除のどの操作もできない

---

### User Story 2 - 作り手が note を書き換える (Priority: P2)

作り手が、下書きの note や公開済みの note の題と本文を書き換える。

**Why this priority**: 公開した後に誤りを直せないと、誤った内容が訪問者に見え続ける。ただし書き換えがなくても、書いて届ける経路は成り立つ。

**Independent Test**: 公開済みの note の題を書き換え、`/notes/{slug}` に書き換えた題が出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 下書きの note がある、**When** 作り手が題と本文を書き換えて保存する、**Then** 書き換えた内容が保存される
2. **Given** 公開済みの note がある、**When** 作り手が題と本文を書き換えて保存する、**Then** 訪問者の `/notes/{slug}` には書き換える前の内容が出たままである
3. **Given** 公開済みの note を書き換えて保存した、**When** 作り手が公開し直す、**Then** 訪問者の `/notes/{slug}` に書き換えた内容が出る

---

### User Story 3 - 作り手が note を完全に削除する (Priority: P3)

作り手が、下書きまたは公開済みの note を完全に削除する。

**Why this priority**: 出すべきでなかったものを消せないと、訪問者に見え続ける。書いて届ける経路と書き換えがあれば、削除がなくても日々の執筆は成り立つ。

**Independent Test**: 公開済みの note を削除し、`/notes/{slug}` で note がないことが伝わる表示になり、`/dash/` からも見えなくなることを確かめる。

**Acceptance Scenarios**:

1. **Given** 公開済みの note がある、**When** 作り手が削除を選ぶ、**Then** 削除してよいかの確認を求められ、確認するまで削除されない
2. **Given** 削除の確認を求められている、**When** 作り手が確認する、**Then** note が完全に消え、訪問者が `/notes/{slug}` を開くと note がないことが伝わる表示になる
3. **Given** note を削除した、**When** 作り手が同じ識別子で note を新しく作る、**Then** その識別子を使える

---

### Edge Cases

- 識別子を入力せずに保存しようとしたとき、識別子が足りないことが分かり、入力した題と本文は失われない
- 英数字とハイフン以外を含む識別子を入力したとき、使えない文字があることが分かる
- 他の note が使っている識別子を入力したとき、その識別子が使えないことが分かる
- 題が空のまま公開しようとしたとき、公開されず、題が足りないことが分かる
- 存在しない識別子で `/notes/{slug}` を開いたとき、note がないことが伝わる表示になる
- 保存の途中で失敗したとき、保存に失敗したことが分かり、公開済みの内容は変わらない

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 作り手は `/dash/` 配下で、題・本文・識別子を入力して note を作れる
- **FR-002**: note は「下書き」と「公開」のどちらかの状態を持つ。作られた note は下書きである
- **FR-003**: 作り手は下書きの note を公開できる
- **FR-004**: 訪問者は、公開された note の題と本文を `/notes/{slug}` で読める
- **FR-005**: 下書きの note は、訪問者が到達できるどの経路にも現れない
- **FR-006**: 識別子は英数字とハイフンだけからなり、存在する note の間で重ならない
- **FR-007**: 識別子は、note を一度公開した後は変えられない
- **FR-008**: 作り手は note の題と本文を書き換えられる。公開済みの note を書き換えた内容は、作り手が公開し直すまで訪問者に見えない
- **FR-009**: 作り手は note を完全に削除できる。削除は、作り手が確認してから行う
- **FR-010**: 作り手以外は、`/dash/` 配下の画面を表示できず、note を作成・保存・公開・削除する操作を行えない
- **FR-011**: 存在しない note と下書きの note への `/notes/{slug}` の要求は、note がないことを訪問者に伝える。両者を区別できる違いを訪問者に見せない
- **FR-012**: 本文は装飾を持たない文章である。訪問者の画面では、作り手が入れた改行の位置で改行して表示する
- **FR-013**: 保存・公開・削除に失敗したとき、作り手は失敗したことを知ることができ、入力中の題と本文は失われない

### Key Entities

- **note**: 作り手が synsk.me で書いて公開する文章1件。識別子・題・本文・状態（下書き / 公開）・初めて公開した日時・最後に書き換えた日時を持つ

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 作り手が `/dash/` を開いてから、note を1件書いて公開し、訪問者の画面で読めるまでを、synsk.me の外の道具を使わずに行える
- **SC-002**: 作り手以外が `/dash/` 配下の画面と操作に到達できる経路が0件である
- **SC-003**: 訪問者の到達する経路に、下書きの note の題・本文が現れる件数が0件である
- **SC-004**: 公開した note の `/notes/{slug}` は、題と本文を書き換えても変わらない
- **SC-005**: 訪問者の到達する経路に、削除した note の題・本文が現れる件数が0件である

## Assumptions

- この spec が扱うのは、1件の note を書いて公開し、読むまでの経路だけである。`/notes` の一覧、題から識別子の候補を出すこと、公開前に見た目を確かめること、画像は扱わない
- 公開済みの note を下書きに戻す操作は扱わない。訪問者に見せたくない note は削除する
- note の見た目は扱わない。訪問者の画面も作り手の画面も、読めて操作できることだけを求める
- 作り手は1人である。複数の作り手が同じ note を同時に書き換える場合は扱わない
- 作り手以外を `/dash/` に入れない仕組みは、`docs/decisions/0013-access-authentication.md` が定めるアプリケーションの外の仕組みによる
- note の保管先は `docs/decisions/0014-authoring-and-datastore.md` が定める。この spec は保管の形式を決めない
- 識別子の規則（英数字、題と別に持つ）は `docs/decisions/0016-url-conventions.md` による
