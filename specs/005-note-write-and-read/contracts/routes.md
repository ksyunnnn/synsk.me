# Contract: 画面と操作

訪問者と作り手が使う経路と、操作の入力・結果を定める。見た目は定めない（spec の Assumptions）。すべての画面とフォームは JavaScript なしで動く。

## 訪問者

### `GET /notes/{slug}`

| 条件 | 状態コード | 表示 |
|---|---|---|
| slug の note が公開されている | 200 | 公開している題、公開日（日本時間の `YYYY-MM-DD`、[data-model.md](../data-model.md)）、本文。本文は作り手が入れた改行の位置で改行する |
| slug の note が下書き | 404 | note がないことを伝える表示 |
| slug の note が削除されている | 404 | 下書きのときと同じ表示 |
| slug の note が存在しない | 404 | 下書きのときと同じ表示 |
| D1 から読み出せない | 500 | 読み出せなかったことを伝える表示。note の題と本文を含めない |

- 下書き・削除した note・存在しない slug への応答は、状態コード・表示・応答のヘッダの名前と値のどれも一致する（FR-011）。要求した slug を写した箇所と、note の状態によらず要求ごとに変わる値（`content-length`、`date`）は比べる対象に含めない
- 表示するのは、最後に公開した版の題と本文だけ。作り手が書き換え中の題と本文（最新の版）は出さない（FR-008）
- 本文は文字列として出す。HTML として解釈しない（FR-012）

## 作り手

`/dash` とその配下のすべての画面と操作は、作り手であることを確かめてから行う。確かめ方は [research.md](../research.md) の R2。

| 条件 | 画面の要求 | 操作の要求 |
|---|---|---|
| 作り手であることを確かめられた | 画面を返す | 操作を行う |
| 確かめられない（証明がない・不正・期限切れ・設定値の欠け） | 403。画面の中身を返さない | 何も書き込まない |
| 操作の要求が synsk.me の画面以外から送られた（要求の Origin が要求先のホストと異なる） | — | 何も書き込まない |

### `GET /dash`

削除していないすべての note を一覧する（FR-014）。1件ごとに次を出す。

- slug、題（空なら空であることが分かる表示）
- 状態: `下書き` か `公開`
- 公開であり、公開し直していない書き換えがあれば、そのことを示す表示
- 編集の画面へのリンク

新しい note を作る画面へのリンクを置く。

その下に、削除した note を一覧する（FR-018）。後から削除したものを先に並べ、1件ごとに次を出す。

- slug、題（空なら空であることが分かる表示）
- 削除する前の状態: `下書き` か `公開`
- 戻す確認の画面へのリンク

- note が0件のときは、note がないことを出す
- 削除した note が0件のときは、削除した note がないことを出す
- D1 から読み出せないときは、500 と、読み出せなかったことを伝える表示を返す

### `GET /dash/notes/new` と「作る」操作

入力: `slug`、`title`、`body`

| 結果 | 次の画面 |
|---|---|
| 作れた | `/dash/notes/{id}` へ移る |
| 入力が規則に合わない | 同じ画面。どの項目の何が合わないかを出し、入力した値を残す |
| slug を他の note が使っている（削除した note を含む） | 同じ画面。その slug が使えないことを出し、入力した値を残す（FR-006） |
| 保存に失敗した | 同じ画面。失敗したことを出し、入力した値を残す（FR-013） |

入力の規則は [data-model.md](../data-model.md)。

### `GET /dash/notes/{id}`

`id` の note の編集の画面。`slug`、`title`、`body` を入力でき、「保存する」と「公開する」の2つの操作を置く。公開済みの note では「公開し直す」と呼ぶ。削除の確認の画面へのリンクを置く。

- 公開済みの note では、slug を変えられないことが分かる形で出す（FR-007）
- `id` の note が存在しないか、削除されていれば 404（FR-019）
- D1 から読み出せないときは、500 と、読み出せなかったことを伝える表示を返す。削除の確認の画面と、戻す確認の画面も同じ

### 「保存する」操作

入力: `noteId`、`slug`、`title`、`body`、押したボタン（`intent`）

| 結果 | 次の画面 |
|---|---|
| 保存できた | 同じ画面（移動しない）。保存したことを出す |
| 入力が規則に合わない、公開済みの note の slug を変えようとした | 同じ画面。理由を出し、入力した値を残す |
| 保存に失敗した | 同じ画面。失敗したことを出し、入力した値を残す。公開している内容は変わらない |
| `id` の note が存在しない（別の画面で削除された） | 書き込みは起きない。note が存在しないことを出す。JavaScript なしの送信では、画面全体を描画し直すため、編集の画面の代わりに `id` の note がない画面（404）になり、入力した値は残らない |

### 「公開する」「公開し直す」操作

入力: `noteId`、`slug`、`title`、`body`、押したボタン（`intent`）。入力した内容の保存と公開を、1つの書き込みとして行う（[data-model.md](../data-model.md) の「状態の移り変わり」）。

| 結果 | 次の画面 |
|---|---|
| 公開できた | 同じ画面（移動しない）。公開したことと、`/notes/{slug}` へのリンクを出す |
| 題が空 | 同じ画面。題が足りないことを出し、入力した値を残す。保存も公開もしない |
| 入力が規則に合わない | 同じ画面。理由を出し、入力した値を残す。保存も公開もしない |
| `id` の note が存在しない（別の画面で削除された） | 書き込みは起きない。note が存在しないことを出す。JavaScript なしの送信では、画面全体を描画し直すため、編集の画面の代わりに `id` の note がない画面（404）になり、入力した値は残らない |
| 失敗した | 同じ画面。失敗したことを出し、入力した値を残す |

### `GET /dash/notes/{id}/delete` と「削除する」操作

削除の確認の画面。削除する note の slug と題、削除した note を戻せることを出し、「削除する」操作と、編集の画面へ戻るリンクを置く（FR-009）。`id` の note が存在しないか、削除されていれば 404。

削除は note のデータを消さない。削除した日時を入れ、訪問者と note の一覧から見えなくする（[data-model.md](../data-model.md) の「状態の移り変わり」）。

入力: `noteId`

| 結果 | 次の画面 |
|---|---|
| 削除できた | `/dash?deleted=1` へ移り、一覧の画面が削除したことを出す |
| `id` の note が存在しないか、削除されている | `/dash` へ移る。書き込みは起きない |
| 失敗した | 同じ確認の画面。失敗したことを出す |

### `GET /dash/notes/{id}/restore` と「戻す」操作

戻す確認の画面。戻す note の slug と題、削除する前の状態（下書き / 公開）を出し、「下書きで戻す」操作と、一覧の画面へ戻るリンクを置く（FR-018）。公開したことのある note には「公開で戻す」操作も置き、公開で戻すと最後に公開した内容を訪問者が再び読めることを出す。公開したことのない note では、公開では戻せないことを出す。「下書きで戻す」を先に置く。`id` の note が存在しないか、削除されていなければ 404。

入力: `noteId`、押したボタンの `restoreAs`（`draft` か `published`）

| 結果 | 次の画面 |
|---|---|
| 戻せた | `/dash?restored=1` へ移り、一覧の画面が戻したことを出す。note は選んだ状態になり、版・最後に公開した版・初めて公開した日時を保つ |
| `id` の note が存在しないか、削除されていない（別の画面で戻された）。または、公開したことのない note を公開で戻そうとした | `/dash` へ移る。書き込みは起きない |
| `restoreAs` が `draft` でも `published` でもない | 同じ確認の画面。失敗したことを出す。書き込みは起きない |
| 失敗した | 同じ確認の画面。失敗したことを出す |
