# Contract: 画面と操作

訪問者と作り手が使う経路と、操作の入力・結果を定める。見た目は定めない（spec の Assumptions）。すべての画面とフォームは JavaScript なしで動く。

## 訪問者

### `GET /notes/{slug}`

| 条件 | 状態コード | 表示 |
|---|---|---|
| slug の note が公開されている | 200 | 公開している題、初めて公開した日（`YYYY-MM-DD`）、本文。本文は作り手が入れた改行の位置で改行する |
| slug の note が下書き | 404 | note がないことを伝える表示 |
| slug の note が存在しない | 404 | 下書きのときと同じ表示。応答から両者を区別できない（FR-011） |

- 表示するのは `note_publication` の値だけ。作り手が書き換え中の題と本文は出さない（FR-008）
- 本文は文字列として出す。HTML として解釈しない（FR-012）

## 作り手

`/dash` とその配下のすべての画面と操作は、作り手であることを確かめてから行う。確かめ方は [research.md](../research.md) の R2。

| 条件 | 画面の要求 | 操作の要求 |
|---|---|---|
| 作り手であることを確かめられた | 画面を返す | 操作を行う |
| 確かめられない（証明がない・不正・期限切れ・設定値の欠け） | 403。画面の中身を返さない | 何も書き込まない |
| 操作の要求が synsk.me の画面以外から送られた（要求の Origin が要求先のホストと異なる） | — | 何も書き込まない |

### `GET /dash`

すべての note を一覧する（FR-014）。1件ごとに次を出す。

- slug、題（空なら空であることが分かる表示）
- 状態: `下書き` か `公開`
- 公開であり、公開し直していない書き換えがあれば、そのことを示す表示
- 編集の画面へのリンク

新しい note を作る画面へのリンクを置く。

### `GET /dash/notes/new` と「作る」操作

入力: `slug`、`title`、`body`

| 結果 | 次の画面 |
|---|---|
| 作れた | `/dash/notes/{id}` へ移る |
| 入力が規則に合わない | 同じ画面。どの項目の何が合わないかを出し、入力した値を残す |
| 保存に失敗した | 同じ画面。失敗したことを出し、入力した値を残す（FR-013） |

入力の規則は [data-model.md](../data-model.md)。

### `GET /dash/notes/{id}`

`id` の note の編集の画面。`slug`、`title`、`body` を入力でき、「保存する」と「公開する」の2つの操作を置く。公開済みの note では「公開し直す」と呼ぶ。削除の確認の画面へのリンクを置く。

- 公開済みの note では、slug を変えられないことが分かる形で出す（FR-007）
- `id` の note が存在しなければ 404

### 「保存する」操作

入力: `id`、`slug`、`title`、`body`

| 結果 | 次の画面 |
|---|---|
| 保存できた | 同じ画面。保存したことを出す |
| 入力が規則に合わない、公開済みの note の slug を変えようとした | 同じ画面。理由を出し、入力した値を残す |
| 保存に失敗した | 同じ画面。失敗したことを出し、入力した値を残す。公開している内容は変わらない |
| `id` の note が存在しない（別の画面で削除された） | 同じ画面。note が存在しないことを出す。書き込みは起きない |

### 「公開する」「公開し直す」操作

入力: `id`、`slug`、`title`、`body`。入力した内容を保存してから、その内容を公開する。

| 結果 | 次の画面 |
|---|---|
| 公開できた | 同じ画面。公開したことと、`/notes/{slug}` へのリンクを出す |
| 題が空 | 同じ画面。題が足りないことを出す。入力した値は保存され、公開はされない |
| 入力が規則に合わない | 同じ画面。理由を出し、入力した値を残す。保存も公開もしない |
| `id` の note が存在しない（別の画面で削除された） | 同じ画面。note が存在しないことを出す。書き込みは起きない |
| 失敗した | 同じ画面。失敗したことを出し、入力した値を残す |

### `GET /dash/notes/{id}/delete` と「削除する」操作

削除の確認の画面。削除する note の slug と題を出し、「削除する」操作と、編集の画面へ戻るリンクを置く（FR-009）。

入力: `id`

| 結果 | 次の画面 |
|---|---|
| 削除できた | `/dash` へ移り、削除したことを出す |
| `id` の note が存在しない | `/dash` へ移る。書き込みは起きない |
| 失敗した | 同じ確認の画面。失敗したことを出す |
