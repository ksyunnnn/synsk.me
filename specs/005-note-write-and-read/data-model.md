# Data Model: note を書いて公開し、読む

保存の正本は `migrations/` の SQL である（[research.md](./research.md) の R1）。この文書は、その SQL が満たすべき形と規則を書く。

## note

作り手が書き換えている内容。行があれば note が存在する。`deleted_at` に日時が入っている note が、削除した note である。

| 項目 | 型 | 規則 | 出典 |
|---|---|---|---|
| id | 整数 | 主キー。id を使い回さない（SQLite の `AUTOINCREMENT`） | spec の Edge Cases（別の画面で削除した note） |
| slug | 文字列 | 1〜100文字。小文字の英字・数字・ハイフンだけ。削除した note を含むすべての note の間で一意 | FR-006、R1 |
| title | 文字列 | 0〜200文字。下書きのうちは空でよい | FR-001、FR-015 |
| body | 文字列 | 0〜100,000文字 | FR-012、FR-015 |
| deleted_at | 日時 | 削除した日時。削除していない note では空（NULL）。戻すと空に戻る | FR-009、FR-018 |

## note_publication

訪問者に見せている内容。行があれば公開、なければ下書き（FR-002）。状態を表す列を持たないため、状態と中身が食い違わない。note を削除しても行を残す。戻した note が、削除する前の状態と初めて公開した日時を保つため（FR-018）。

| 項目 | 型 | 規則 | 出典 |
|---|---|---|---|
| note_id | 整数 | 主キー。`note.id` を指す。`note` の行を Cloudflare の管理画面から消すと一緒に消える（外部キーの `ON DELETE CASCADE`） | FR-020 |
| title | 文字列 | 1〜200文字。空の題では公開できない | spec の Edge Cases、FR-015 |
| body | 文字列 | 0〜100,000文字 | FR-015 |
| first_published_at | 日時 | 初めて公開した日時。公開し直しても変わらない | FR-004 |

## 文字数の数え方

文字数は Unicode のコードポイントで数える。SQLite の `length()` と同じ数え方で、JavaScript では `[...value].length` にあたる。JavaScript の `value.length`（UTF-16 のコード単位）は使わない。絵文字1文字を2と数え、データベースの検査と判定が食い違うため。

## 日時の形

`2026-09-17T10:00:00.000Z` の形の文字列（JavaScript の `Date.prototype.toISOString()` が返す形）。UTC で保存する。文字列の並びと時刻の並びが一致する。

訪問者の画面に出す公開日は、この日時を日本時間（Asia/Tokyo）に直した日付（`YYYY-MM-DD`）とする（FR-004）。たとえば `2026-09-16T15:30:00.000Z` は `2026-09-17` になる。

## 状態の移り変わり

```
（なし） ──作る──▶ 下書き ──公開する──▶ 公開
                    │  ▲               │  ▲  ▲
                    │  │               │  │  └─公開し直す（題と本文を写し直す。first_published_at は変えない）
               削除する  戻す        削除する  戻す
                    ▼  │               ▼  │
              削除した下書き        削除した公開
```

- 保存は `note` にだけ書く。公開済みの note を保存しても、訪問者に見える内容は変わらない（FR-008）
- 公開と公開し直しは、入力した内容を `note` に保存し、その題と本文を `note_publication` へ写す。2つの書き込みは `db.batch()` で原子的に行い、片方だけが残ることはない
- 公開済みの note を下書きに戻す操作はない（spec の Assumptions）
- 削除は `note.deleted_at` に日時を入れる。行を消さず、`note_publication` にも触れない。戻すときは `deleted_at` を空に戻す（FR-009、FR-018）
- 削除した note は、保存・公開・編集の画面の取り出し・訪問者向けの取り出しのどれからも、存在しない note と同じに扱う（FR-011、FR-019）。削除した note を扱うのは、戻す操作と、削除した note の一覧と、戻す確認の画面だけである
- 行を消す操作をアプリケーションは持たない。完全に消すのは Cloudflare の管理画面から行う（FR-020）

## 導かれる値

| 値 | 求め方 | 使う場所 |
|---|---|---|
| 状態 | `note_publication` に行があれば公開、なければ下書き | 作り手の一覧（FR-014）、削除した note の一覧（FR-018） |
| 削除した note | `note.deleted_at` が空でない | 削除した note の一覧（FR-018） |
| 公開し直していない書き換えがある | 公開であり、かつ `note` と `note_publication` の題か本文が異なる | 作り手の一覧（FR-014） |

## データベースで止める規則

アプリケーションの検査を抜けても、データベースが次を拒む。

- slug の文字種・長さ・重複
- 題と本文の長さ
- 空の題の公開
- 日時の形
- 公開した note の slug の変更（FR-007）
