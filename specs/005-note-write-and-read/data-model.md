# Data Model: note を書いて公開し、読む

保存の正本は `migrations/` の SQL である（[research.md](./research.md) の R1）。この文書は、その SQL が満たすべき形と規則を書く。

## note

note そのもの。行があれば note が存在する。`deleted_at` に日時が入っている note が、削除した note である。題と本文は持たず、`note_revision` の版が持つ。

| 項目 | 型 | 規則 | 出典 |
|---|---|---|---|
| id | 整数 | 主キー。id を使い回さない（SQLite の `AUTOINCREMENT`） | spec の Edge Cases（別の画面で削除した note） |
| slug | 文字列 | 1〜100文字。小文字の英字・数字・ハイフンだけ。削除した note を含むすべての note の間で一意。公開したことがあれば変えられない | FR-006、FR-007、R1 |
| status | 文字列 | `draft`（下書き）か `published`（公開）。作ったときは `draft` | FR-002 |
| published_revision_id | 整数 | 最後に公開した版。公開したことのない note では空（NULL）。同じ note の、題が空でない版だけを指す。下書きで戻した note でも残す | FR-008、FR-018 |
| published_at | 日時 | 初めて公開した日時。公開したことのない note では空。一度入れたら変えない | FR-004 |
| deleted_at | 日時 | 削除した日時。削除していない note では空。戻すと空に戻る | FR-009、FR-018 |

`published_revision_id` と `published_at` は、どちらもあるか、どちらも空である。`status` が `published` なら `published_revision_id` がある。

## note_revision

note の題と本文の版。保存と公開のたびに1行足す。題と本文が最新の版と同じなら足さない。行を書き換えない。アプリケーションは行を消さない（FR-021）。

| 項目 | 型 | 規則 | 出典 |
|---|---|---|---|
| id | 整数 | 主キー。大きいほど新しい版（SQLite の `AUTOINCREMENT`） | FR-021 |
| note_id | 整数 | `note.id` を指す。`note` の行を Cloudflare の管理画面から消すと一緒に消える（外部キーの `ON DELETE CASCADE`） | FR-020 |
| title | 文字列 | 0〜200文字。下書きのうちは空でよい。空の題の版は公開できない | FR-001、FR-015、spec の Edge Cases |
| body | 文字列 | 0〜100,000文字 | FR-012、FR-015 |
| created_at | 日時 | 版を作った日時 | FR-021 |

作り手が書き換えている内容は、note の最新の版（`id` が最大の版）である。訪問者に見せる内容は、`note.published_revision_id` の版である。

版の数に上限を設けない。`docs/SOFTWARE_DESIGN.md` の原則2は量に上限を設けることを求めるが、上限を設けると、古い版を消すか、上限を超えた保存を止めることになる。前者は note の経緯を失い、後者は作り手が書けなくなる。どちらも FR-021 に反するため、原則2を破る。版の量が D1 の上限に近づいたかは、`npx wrangler d1 info synsk-me` が返す DB の大きさで確かめる。

## 文字数の数え方

文字数は Unicode のコードポイントで数える。SQLite の `length()` と同じ数え方で、JavaScript では `[...value].length` にあたる。JavaScript の `value.length`（UTF-16 のコード単位）は使わない。絵文字1文字を2と数え、データベースの検査と判定が食い違うため。

## 日時の形

`2026-09-17T10:00:00.000Z` の形の文字列（JavaScript の `Date.prototype.toISOString()` が返す形）。UTC で保存する。文字列の並びと時刻の並びが一致する。

訪問者の画面に出す公開日は、この日時を日本時間（Asia/Tokyo）に直した日付（`YYYY-MM-DD`）とする（FR-004）。たとえば `2026-09-16T15:30:00.000Z` は `2026-09-17` になる。

## 状態の移り変わり

| 操作の前 | 操作 | 操作の後 |
|---|---|---|
| （なし） | 作る | 下書き |
| 下書き | 公開する | 公開 |
| 公開 | 公開し直す | 公開。初めて公開した日時は変えない |
| 下書き・公開 | 削除する | 削除した note |
| 削除した note | 下書きで戻す | 下書き |
| 削除した note（公開したことのあるものだけ） | 公開で戻す | 公開。最後に公開した版を見せる |

- 作るときは、`note` の行と最初の版を足す
- 保存は版を1つ足す。訪問者に見せる版は変わらない（FR-008）
- 公開と公開し直しは、入力した内容を版として足し、その版を `published_revision_id` にする。`published_at` は空のときだけ入れる。書き込みは `db.batch()` で原子的に行い、一部だけが残ることはない
- 公開済みの note を下書きにするのは、削除した note を下書きで戻すときだけである（spec の Assumptions）
- 削除は `note.deleted_at` に日時を入れる。行も版も消さない（FR-009）
- 戻すときは `deleted_at` を空にし、作り手が選んだ状態を `status` に入れる。下書きで戻しても `published_revision_id` と `published_at` は残る（FR-018）
- 削除した note は、保存・公開・編集の画面の取り出し・訪問者向けの取り出しのどれからも、存在しない note と同じに扱う（FR-011、FR-019）。削除した note を扱うのは、戻す操作と、削除した note の一覧と、戻す確認の画面だけである
- 行を消す操作をアプリケーションは持たない。完全に消すのは Cloudflare の管理画面から行う（FR-020）

## 導かれる値

| 値 | 求め方 | 使う場所 |
|---|---|---|
| 公開したことがある | `published_at` が空でない | 編集の画面（slug を変えられない）、戻す確認の画面（公開で戻せる） |
| 削除した note | `note.deleted_at` が空でない | 削除した note の一覧（FR-018） |
| 公開し直していない書き換えがある | 公開であり、かつ最新の版と `published_revision_id` の版の題か本文が異なる | 作り手の一覧（FR-014） |

## データベースで止める規則

アプリケーションの検査を抜けても、データベースが次を拒む。

- slug の文字種・長さ・重複
- 題と本文の長さ
- 日時の形
- 公開したことのある note の slug の変更（FR-007）
- 初めて公開した日時の変更（FR-004）
- 空の題の版や、別の note の版を公開すること
- 公開した版を持たない公開
- 版の書き換え（FR-021）
