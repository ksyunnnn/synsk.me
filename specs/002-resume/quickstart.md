# Quickstart: 職務経歴書

002 が動くことを確かめる手順。経路と DTO は [contracts/](./contracts/) が、決まりは [data-model.md](./data-model.md) が持つ。

## 前提

- 001 の Phase 1・2 が feature/72-rebuild に入っている。検査は写し元の行を `tests/support/career-and-project-rows.ts` で入れるため、001 の管理画面に依らない。手で確かめる手順の 3 は、001 の User Story 1（実績）と User Story 5（職歴と学歴）の管理画面を使う（tasks.md の「001 への依存」）
- `npm ci` を済ませている
- 例の値はすべて作り物

## 検査を回す

| 段階 | コマンド | 確かめること |
|---|---|---|
| 単体 | `npm test` | 写し方・鍵の作り方と比べ方・識別子の決まり・スキルの一覧・proxy の rewrite とヘッダ |
| workerd | `npm run test:workers` | Repository の実装が本物の migration の上で動く。作成の `batch()`・楽観ロック・削除の順序・中身を返す条件 |
| 結合 | `npm run test:integration` | `/resume/*` の 200・404 とヘッダ（SC-003・SC-005）、元を直しても変わらないこと（SC-001）、`/dash/resumes` の 403、JWT のない書き込みが何も書かないこと |
| E2E | `npm run test:e2e` | 作り手としての作成・編集・状態の切り替え・削除、同時編集、キーボードだけの操作 |
| 型・lint・整形 | `npx tsc --noEmit`、`npm run lint`、`npm run format:check` | 0 件 |

## 手で確かめる（ブランチの Preview）

Preview は全体が Access の後ろにある（README.md の「開発」）。鍵の URL を、ログインしていない状態で開く確かめは結合の検査が持つ。

1. `npm run build` が通る
2. Preview の D1 に migration が当たっている
3. 作り物の職歴 2 件・実績 3 件（うち 1 件は秘匿化）・学歴 1 件を登録する
4. `/dash/resumes/new` を開き、すべてが選ばれていることを確かめ、実績を 1 件外して、限定公開用のまま作る。示された URL を控える
5. 状態を訪問者に見せるに切り替え、控えた URL を開く。秘匿化した実績が実際の題と組織名で出て、外した実績が出ない
6. 元の実績の題を直し、元の学歴を消す。控えた URL で、作ったときの題と学歴が出る
7. 期限を過去の日時にすると 404、先の日時に延ばすと同じ URL で読める
8. 鍵の最後の 1 文字を変えた URL が 404 を返す
9. 「PDF で保存」のボタンでブラウザの印刷の画面が開き、PDF に保存したファイルで日本語が読め、ボタンと管理画面への導線が載らない
10. 2 つのタブで同じ職務経歴書を開き、片方で保存した後にもう片方で保存すると、保存されずに入力が残り、知らせが出る

公開用の確かめ: 秘匿化した実績と秘匿化しない実績を 1 件ずつ載せた公開用を作り、`/resume/{slug}` の HTML に、秘匿化した実績の実際の題・組織名・本文が無い。メールアドレスのスパム対策は本番の応答で確かめる（plan.md の U8）。
