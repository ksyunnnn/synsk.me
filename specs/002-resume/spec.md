## Terms

- **オーナー**、**訪問者**、**組織**、**職歴**、**実績**、**秘匿化**、**本文**: [001 の spec](../001-career-and-project/spec.md) の Terms と同じ意味で使う
- **職務経歴書**: オーナーが職歴・実績・学歴・スキルから載せるものを選んで作る文書。オーナーは職務経歴書を複数持てる
- **限定公開用**: 転職活動で、提出先ごとに内容を変えて渡す職務経歴書。「限定公開」という語は職務経歴書にだけ使う
- **公開用**: サイトで訪問者に公開する職務経歴書
- **写す**: 職務経歴書を作るとき、元の職歴・実績・学歴・スキルの値を、その職務経歴書だけの値として持つこと。写した値は元と切り離され、元を直しても変わらない。プロフィールは写さない
- **鍵**: 限定公開用の URL に含め、その職務経歴書を読むために要る値
- **期限**: 限定公開用の URL で読める最後の日時。期限を設けないこともできる
- **プロフィール**: オーナーの氏名・自己紹介・メールアドレスなど

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 職歴と項目を選んで職務経歴書を作る (Priority: P1)

オーナーは管理画面で職務経歴書を作る。限定公開用か公開用かの既定は限定公開用で、オーナーは公開用に変えて作れる。職歴・実績・学歴の選択肢は、最初はすべて選ばれており、オーナーは載せないものを外す。作った職務経歴書は、選んだ職歴・実績・学歴とスキルを、作ったときの値で写して持つ。

**Why this priority**: 職務経歴書のほかの機能はすべて、写した中身を前提にする。

**Independent Test**: 作り物の職歴 2 件・実績 3 件・学歴 1 件を登録し、実績を 1 件外して限定公開用の職務経歴書を作る。管理画面で、職歴 2 件・実績 2 件・学歴 1 件が載り、外した実績が載らないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 職歴・実績・学歴が登録してある, **When** オーナーが職務経歴書の作成を始める, **Then** すべての職歴・実績・学歴が選ばれた状態で示される
2. **Given** 作成の画面で実績を 1 件外した, **When** オーナーが職務経歴書を作る, **Then** 外した実績は職務経歴書に載らず、ほかは載る
3. **Given** 職務経歴書に載せた職歴・実績・学歴, **When** オーナーが職務経歴書を開く, **Then** 職歴・実績・学歴のそれぞれが、始まりの日の新しい順に並ぶ
4. **Given** 作成の画面, **When** オーナーが限定公開用か公開用かを変えずに作る, **Then** 限定公開用として作られる

---

### User Story 2 - 限定公開用を提出先に渡す (Priority: P1)

オーナーは提出先ごとに限定公開用の職務経歴書を作り、その URL を渡す。URL を知っている人は誰でも読め、ダウンロードできる。限定公開用には、秘匿化するかどうかに関わらず、すべての職歴・実績が実際の組織名・題・本文で載る。オーナーは URL に期限を設けるか、期限を設けないかを選べる。

**Why this priority**: 転職活動で提出先に渡すことが、職務経歴書を複数持つ理由である。

**Independent Test**: 秘匿化した作り物の実績を載せた限定公開用の職務経歴書を作り、訪問者に見せる状態にする。ログインしていない状態でその URL を開き、実際の題と実際の組織名が表示されること、ダウンロードできることを確かめる。

**Acceptance Scenarios**:

1. **Given** 秘匿化した実績を載せた限定公開用の職務経歴書が訪問者に見せる状態にある, **When** URL を知っている人が開く, **Then** 実績の実際の題と実際の組織名と本文が表示される
2. **Given** 限定公開用の職務経歴書, **When** 鍵を含まない URL、または鍵が違う URL で開く, **Then** 中身は表示されない
3. **Given** 期限を過ぎた限定公開用の職務経歴書, **When** URL を知っている人が開く, **Then** 中身は表示されない
4. **Given** 期限を過ぎた限定公開用の職務経歴書, **When** オーナーが期限を先の日時に延ばす, **Then** 同じ URL でもう一度読める
5. **Given** 期限を設けない限定公開用の職務経歴書, **When** 作ってから時間がたって開く, **Then** 中身が表示される
6. **Given** 限定公開用の職務経歴書の URL, **When** その応答を調べる, **Then** 検索エンジンの結果に出ない扱いになっており、キャッシュに残らない

---

### User Story 3 - 元を直しても、渡した職務経歴書は変わらない (Priority: P1)

オーナーが元の職歴・実績・学歴・組織名・スキルを直しても、削除しても、作った職務経歴書の中身は変わらない。プロフィールはこの範囲に含まない。プロフィールを直すと、作ったすべての職務経歴書に直した値が出る。

**Why this priority**: 渡した職務経歴書の中身が、渡したあとに変わると、提出先が読んだ内容と食い違う。

**Independent Test**: 職務経歴書を作ったあと、元の実績の題と組織名を直し、元の学歴を 1 件削除する。職務経歴書を開き、作ったときの題・組織名・学歴が表示されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 職務経歴書に写した実績, **When** オーナーが元の実績の題を直す, **Then** 職務経歴書の題は作ったときの値のまま
2. **Given** 職務経歴書に写した職歴, **When** オーナーが元の組織名を直す, **Then** 職務経歴書の組織名は作ったときの値のまま
3. **Given** 職務経歴書に写した学歴, **When** オーナーが元の学歴を削除する, **Then** 職務経歴書の学歴は残る
4. **Given** 職務経歴書に写したスキル, **When** オーナーが元のスキルの経験年数の上書きを直す, **Then** 職務経歴書の経験年数は変わらない

---

### User Story 4 - 職務経歴書ごとに中身を直す (Priority: P2)

オーナーは作った職務経歴書の中で、写した値を直せる。直せる範囲に制限はない。直しても、元の職歴・実績・学歴・組織・スキルは変わらない。

**Why this priority**: 提出先ごとに書き方を微調整する。秘匿化した組織名を職務経歴書ごとに変えたいときも、職務経歴書の中で直す。

**Independent Test**: 職務経歴書の中で職歴の組織名と実績の本文を直し、職務経歴書に直した値が表示されること、元の組織名と実績の本文が変わらないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 職務経歴書に写した職歴, **When** オーナーが職務経歴書の中で組織名を直す, **Then** その職務経歴書には直した組織名が表示され、元の組織と、ほかの職務経歴書は変わらない
2. **Given** 職務経歴書に写した実績, **When** オーナーが職務経歴書の中で始まりの日を直す, **Then** その職務経歴書の並び順と、スキルの経験年数に直した日が使われる

---

### User Story 5 - 公開用をサイトで見せる (Priority: P2)

オーナーはサイトで公開する職務経歴書を 1 つ持つ。公開用では、秘匿化しない職歴・実績は実際の値と本文で載り、秘匿化した職歴・実績だけが秘匿化した値で載って本文・画像・関連 URL を伏せる。訪問者は公開用の職務経歴書を期限なく読め、PDF でダウンロードできる。

**Why this priority**: サイトで経歴を見せる入口になる。限定公開用より後でも、提出先に渡す用途は満たせる。

**Independent Test**: 秘匿化した作り物の実績と秘匿化しない作り物の実績を 1 件ずつ載せた公開用の職務経歴書を作り、訪問者に見せる状態にする。訪問者への応答に、秘匿化した実績の実際の題・実際の組織名・本文の中身が含まれないこと、秘匿化しない実績が実際の題・実際の組織名・本文で表示されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 秘匿化した実績を載せた公開用の職務経歴書が訪問者に見せる状態にある, **When** 訪問者が開く, **Then** 秘匿化した題と秘匿化した組織名で表示され、本文は伏せた見た目で表示される
2. **Given** 公開用の職務経歴書, **When** 訪問者への応答を調べる, **Then** 秘匿化した実績の実際の題・実際の組織名・本文の中身・本文の画像・関連 URL が含まれない
3. **Given** 下書きの公開用の職務経歴書, **When** 訪問者がその URL を開く, **Then** 中身は表示されない
4. **Given** 秘匿化しない実績（例: 作り物の「個人開発のアプリ」）を載せた公開用の職務経歴書が訪問者に見せる状態にある, **When** 訪問者が開く, **Then** 実際の題と実際の組織名と本文が表示される
5. **Given** 秘匿化した実績を載せた公開用の職務経歴書が訪問者に見せる状態にある, **When** 訪問者が PDF をダウンロードする, **Then** PDF に秘匿化した実績の実際の題・実際の組織名・本文の中身・本文の画像・関連 URL が含まれない

---

### Edge Cases

- 下書きの限定公開用の職務経歴書は、鍵が合っていて期限の前でも、中身を表示しない
- 期限が切れた限定公開用の職務経歴書は消えない。管理画面ではオーナーが読める
- 作ったあとに、限定公開用を公開用へ、公開用を限定公開用へ変えることはできない
- 写し元の職歴・実績・学歴を削除しても、写した職務経歴書の中身は残る
- 職務経歴書に写した実績の始まりの日をオーナーが直すと、その職務経歴書の並び順が変わる

## Requirements *(mandatory)*

### Functional Requirements

**作成と写し**

- **FR-001**: オーナーは職務経歴書を複数作れる。職務経歴書ごとに題と、URL に出す識別子を持つ
- **FR-002**: 職務経歴書の識別子は 1〜100 文字の英小文字・数字・ハイフンで、ほかの職務経歴書と重ならない
- **FR-037**: 限定公開用の識別子は、題や提出先から推測できない uid である。作ったあとに書き換えられない
- **FR-039**: 公開用の識別子は、既定で uid である。オーナーは読みやすい識別子（例: resume）に書き換えられる
- **FR-003**: 職務経歴書を作るとき、限定公開用か公開用かの既定は限定公開用である。オーナーは公開用に変えて作れる
- **FR-004**: 限定公開用か公開用かは、作ったあとに変えられない
- **FR-005**: 職務経歴書を作る画面は、すべての職歴・実績・学歴を選んだ状態で始まる。オーナーは載せないものを外せる
- **FR-006**: 職務経歴書に載せる項目は、職歴・実績・学歴・スキルとプロフィールである
- **FR-034**: プロフィールは 1 つだけである。オーナーは管理画面でプロフィールを書き換えない
- **FR-035**: プロフィールのメールアドレスは訪問者に出してよい。出すときはスパム対策をする
- **FR-036**: 職務経歴書を作るとき、プロフィールは写さない。プロフィールを直すと、作ったすべての職務経歴書（限定公開用・公開用。PDF を含む）に直した値が出る
- **FR-007**: 職務経歴書を作るとき、選んだ職歴・実績・学歴の値を、その職務経歴書だけの値として写す。元の職歴・実績・学歴・組織・スキルを直しても削除しても、写した値は変わらない。プロフィールは写さない（FR-036）
- **FR-008**: 組織名と実績の題は、その職務経歴書で使う方の値だけを写す。限定公開用は実際の組織名と実際の題を写す。公開用は、秘匿化しない職歴・実績では実際の組織名と実際の題を、秘匿化した職歴・実績では秘匿化した組織名と秘匿化した題を写す
- **FR-009**: 職務経歴書の中の職歴・実績・学歴は、それぞれ始まりの日の新しい順に並ぶ。オーナーが手で並べ替える機能は持たない

**限定公開用**

- **FR-010**: 限定公開用には、秘匿化するかどうかに関わらず、すべての職歴・実績を実際の組織名・題・本文で載せる
- **FR-011**: 限定公開用の URL は、識別子に加えて鍵を含む。鍵が合わない URL では中身を返さない
- **FR-012**: 鍵は、保存したデータが漏れても URL が分からない形で持つ。鍵を平文で保存しない
- **FR-013**: オーナーは限定公開用の期限を、日時で設けるか、設けないかを選べる。期限を設けなければ、期限なく読める
- **FR-014**: 期限を過ぎた限定公開用は中身を返さない。職務経歴書は消さず、オーナーが期限を延ばせば、同じ URL でもう一度読める
- **FR-015**: 限定公開用は検索エンジンの結果に出さない。限定公開用の応答はどのキャッシュにも残らない。URL を手に入れた人が読むことは許す

**公開用**

- **FR-016**: 公開用は、職務経歴書を作ったときの職歴・実績の秘匿化するかどうかに従う。公開用には、秘匿化しない職歴・実績を実際の組織名・題・本文で載せる。秘匿化した職歴・実績だけを、秘匿化した組織名と秘匿化した題で載せる（001 の FR-019・FR-020・FR-023 と同じ）
- **FR-017**: 公開用で秘匿化した職歴・実績の本文は伏せた見た目で出し、本文の中身・画像・関連 URL を訪問者への応答に含めない（001 の FR-021・FR-026・FR-030 と同じ）
- **FR-018**: 公開用で秘匿化した職歴・実績について、訪問者に出してよい値は、秘匿化した組織名・秘匿化した題と、期間・種類・肩書・使ったスキルだけである（001 の FR-026 と同じ）
- **FR-019**: 公開用の職務経歴書は 1 つだけである。2 つ目の公開用は、保存する前に拒まれる
- **FR-020**: 公開用は鍵と期限を持たず、訪問者に見せる状態の間は期限なく読める

**見せるかどうか**

- **FR-021**: 職務経歴書は、下書きか、訪問者に見せるかの状態を持つ。作ったときの状態は下書きである。オーナーが職務経歴書ごとに切り替える
- **FR-022**: 下書きの職務経歴書は、限定公開用・公開用のどちらも訪問者に中身を返さない
- **FR-023**: 限定公開用が中身を返すのは、訪問者に見せる状態で、鍵が合い、期限の前か期限を設けていないときに限る
- **FR-024**: 職務経歴書に載せた学歴は、職務経歴書を通して訪問者に出す

**スキル**

- **FR-025**: 職務経歴書を作るとき、載せた実績につないだスキルの名前を、その実績とともに写す
- **FR-026**: 職務経歴書のスキルの一覧は、写したスキルの名前から求める。同じ名前のスキルは 1 つとして数える
- **FR-027**: 職務経歴書のスキルの経験年数は、写したスキルをつないだ写した実績の期間をつなぎ、重なりを除いた長さから求める。経験年数は年と月で表す。終わりの日が空の実績は、求める日までの期間として数える（001 の FR-033 と同じ）。求めた値は保存しない
- **FR-028**: 元のスキルに経験年数の上書きがあれば、職務経歴書を作るときにその値を写す。写した上書きがあるスキルは、求めた値の代わりに写した値を使う

**ダウンロード**

- **FR-029**: 限定公開用・公開用の職務経歴書を読める人は、それを PDF のファイルとしてダウンロードできる。公開用の PDF は公開用の表示と同じ値で作り、秘匿化した職歴・実績は秘匿化した値で載せ、本文・画像・関連 URL を含めない
- **FR-030**: ダウンロードのファイルは、求められたときに写した中身から作る。中身はそのときの職務経歴書の表示と同じ値を使う

**書き換え**

- **FR-031**: オーナーは職務経歴書の中の写した値（組織名・題・肩書・期間・本文・関連 URL・種類・学校・学部・備考・スキル・経験年数の上書き）をどれでも直せる。写した値のうち直せるものを制限しない。職歴・実績ごとの秘匿化するかどうかは写した値ではなく、職務経歴書の中で変えられない
- **FR-032**: 職務経歴書の中で直した値は、その職務経歴書にだけ効く。元の職歴・実績・学歴・組織・スキルと、ほかの職務経歴書は変わらない
- **FR-033**: 職務経歴書を作る・直す・期限を変える・状態を切り替える・削除するのはオーナーだけである。訪問者はこれらを行えない
- **FR-038**: 職務経歴書を別の画面で先に書き換えていたら、あとから保存しようとした内容で上書きせずに保存を止め、手元の内容を残して知らせる

### Key Entities *(include if feature involves data)*

- **職務経歴書**: 題・識別子・限定公開用か公開用か・下書きか訪問者に見せるか・作った日時・直した日時を持つ。限定公開用は鍵と期限を持つ。プロフィールは写さず、1 つのプロフィールの値をそのまま出す
- **写した職歴**: 1 つの職務経歴書に属する。組織名・肩書・期間・本文・関連 URL を持ち、写し元の職歴を指す。写し元が無くなっても残る
- **写した実績**: 1 つの職務経歴書に属する。組織名・種類・題・期間・本文・関連 URL を持ち、写し元の実績を指す。写し元が無くなっても残る
- **写した学歴**: 1 つの職務経歴書に属する。学校・学部・期間・備考を持ち、写し元の学歴を指す。写し元が無くなっても残る
- **写したスキル**: 写した実績ごとに、使ったスキルの名前を持つ。同じ実績に同じ名前を 2 回持たない
- **写した経験年数の上書き**: 職務経歴書ごとに、上書きのあるスキルだけ、スキルの名前と、年と月で表した経験年数を持つ

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 元の職歴・実績・学歴・組織・スキルを直す・削除する検査のすべてで、作った職務経歴書の表示とダウンロードのファイルの値が、作ったときの値と一致する
- **SC-002**: 公開用の職務経歴書の訪問者への応答とダウンロードに、秘匿化した職歴・実績の実際の組織名・実際の題・本文の中身・本文の画像・関連 URL が 0 件含まれる
- **SC-003**: 下書き・期限切れ・鍵が合わない・鍵が無いの 4 つの状態の限定公開用の URL のすべてで、訪問者への応答に職務経歴書の中身が 0 件含まれる
- **SC-004**: 期限切れの限定公開用の期限を延ばしたあと、同じ URL で中身を読める
- **SC-005**: 限定公開用の応答のすべてが、検索エンジンの結果に出ない扱いになっており、キャッシュに残らない
- **SC-006**: 作成の画面を開いたとき、登録したすべての職歴・実績・学歴が選ばれている

## Assumptions

**ほかの spec との関係**

- 職歴・実績・学歴・組織・スキルの登録と、職務経歴書の外での見せ方は [001 の spec](../001-career-and-project/spec.md) が持つ。この spec はそれらを写して職務経歴書を作る
- 経験年数の求め方と表し方は 001 の FR-033・FR-034 と同じである
- 秘匿化した職歴・実績で訪問者に出してよい値は 001 の FR-026 と同じである
- 学歴を訪問者に出すのは職務経歴書を通してだけである（001 の FR-037）
- 完全に削除できること（FR-11）、公開されたときの見た目を公開前に確認できること（FR-13）、保存操作をせずに編集内容が保持されること（FR-14）、公開していない内容を範囲の外の人への応答に含めないこと（NFR-08）、応答をキャッシュに残さないこと（NFR-09）は [REQUIREMENTS.md](../../docs/REQUIREMENTS.md) が持つ
- 写し元を削除しても写した中身を残すことは、この spec が持つ（001 の Assumptions が委ねる）

**実装のときに決める**

- 公開用で、秘匿化した職歴・実績の本文を写すか。どちらでも FR-017 を満たす
- PDF を作る仕組み
- メールアドレスのスパム対策の方法。実装のときに確かめて決める

**決定が無く、この spec では決めない**

- 職歴・実績・学歴を 1 件も選ばずに職務経歴書を作れるか
- 作ったあとに、元から職歴・実績・学歴を足す・元の値で写し直す機能
- 職務経歴書の中で、職歴ごとの実績や職歴ごとのスキルを出すか
- 写した本文の中の画像（写し元の実績・職歴が持つ画像）を、写し元を削除したあとにどう扱うか
- 中身を返さないとき（下書き・期限切れ・鍵が合わない）に訪問者に何を示すか
- 職務経歴書の題を訪問者に出すか
- 期限の既定の値と、期限を選ぶ画面の形
- 伏せた見た目の本文の具体的な形
