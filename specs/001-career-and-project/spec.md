# Feature Specification: 職歴と実績

**Feature Branch**: `feature/72-rebuild`

**Created**: 2026-11-04

**Status**: Draft

**Input**: User description: "職歴と実績: オーナーが所属した組織・職歴・実績（活動を含む）・学歴・スキルを管理画面で登録・編集し、職歴と実績を訪問者に見せる。実績は slug の URL で個別のページを持つ。秘匿化した職歴・実績は秘匿化した値で出し、説明文と本文の画像を伏せる。スキルの経験年数は実績の期間から自動で求め、手で上書きできる。"

## Terms

- **オーナー**: synsk.me の持ち主。管理画面で書き換えられるのはオーナー 1 人だけ
- **訪問者**: 管理画面の外からサイトを見る人
- **組織**: オーナーが所属した組織。会社・団体・自営業（個人）を含む
- **職歴**: 組織にオーナーが所属して働いた履歴
- **実績**: いずれかの組織で実際に担当した仕事・企画と、活動（勉強会の開催・登壇など）。実績は組織に所属する。種類はアプリ・登壇・イベント・その他の 4 つ
- **サイトに載せる**: 職歴・実績を、職務経歴書の外で訪問者に見せること。載せない職歴・実績は、管理画面と、限定公開用の職務経歴書を作るときにだけ使う
- **秘匿化**: 職歴・実績を、実際の組織名・題の代わりに秘匿化した組織名・題で訪問者に出し、説明文と画像を伏せること
- **本文**: 職歴・実績の説明文。画像とそのキャプションを中に置く

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 実績を登録し、個別のページで見せる (Priority: P1)

オーナーは管理画面で実績を登録する。組織・種類・題・秘匿化した題・期間・本文・関連 URL・使ったスキル・秘匿化するかどうか・サイトに載せるかどうかを入れる。訪問者は、サイトに載せる実績の識別子（slug）を含む URL で、その実績の個別のページを開ける。

**Why this priority**: 実績はサイトで訪問者に見せる経歴の中心であり、個別のページを持つのは実績だけである。

**Independent Test**: サイトに載せる、秘匿化しない実績を 1 件登録し、訪問者としてその実績の URL を開いて、題・組織名・期間・本文が登録した値で表示されることを確かめる。

**Acceptance Scenarios**:

1. **Given** サイトに載せる、秘匿化しない実績が 1 件ある, **When** 訪問者がその実績の URL を開く, **Then** 実際の題と実際の組織名と本文が表示される
2. **Given** 実績の登録の画面, **When** オーナーが秘匿化するかどうかを変えずに保存する, **Then** 秘匿化した実績として保存される
3. **Given** 実績が 1 件ある, **When** オーナーが同じ識別子で別の実績を保存する, **Then** 保存されない
4. **Given** 存在しない識別子, **When** 訪問者がその URL を開く, **Then** 見つからないことが示される
5. **Given** 実績の登録の画面, **When** オーナーがサイトに載せるかどうかを変えずに保存する, **Then** サイトに載せない実績として保存される
6. **Given** サイトに載せない実績, **When** 訪問者がその実績の URL を開く, **Then** 存在しない識別子と同じく、見つからないことが示される

---

### User Story 2 - 秘匿化した職歴・実績を、実際の値を出さずに見せる (Priority: P1)

オーナーは職歴・実績ごとに秘匿化するかどうかを選ぶ。サイトに載せる職歴・実績のうち、秘匿化したものは、訪問者に秘匿化した値で出し、本文と画像を伏せる。

**Why this priority**: 取引先などの実際の値が一度訪問者に出ると取り消せない。

**Independent Test**: 秘匿化した実績と職歴を 1 件ずつ登録し、訪問者への応答に実際の組織名・実際の題・本文・画像が含まれないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 秘匿化した実績, **When** 訪問者がその実績を見る, **Then** 秘匿化した題と秘匿化した組織名で表示され、本文は伏せた見た目で表示される
2. **Given** 秘匿化した実績, **When** 訪問者への応答を調べる, **Then** 実際の題・実際の組織名・本文の中身・画像・関連 URL が含まれない
3. **Given** 秘匿化した職歴, **When** 訪問者がその職歴を見る, **Then** 秘匿化した組織名で表示され、本文は伏せた見た目で表示され、画像は表示されない
4. **Given** 秘匿化しない実績（例: 作り物の「個人開発のアプリ」）, **When** 訪問者が見る, **Then** 実際の値と本文と画像が表示される

---

### User Story 3 - 組織を表記をぶらさずに登録する (Priority: P2)

オーナーは職歴・実績を登録するとき、組織名を自由に入力するか、過去に入力した組織名から選ぶ。組織名を直すと、その組織を指す職歴と実績の表示が変わる。

**Why this priority**: 同じ組織が別の表記で登録されると、職歴と実績の対応やスキルの集計が崩れる。

**Independent Test**: 組織名を 1 つ入れて職歴と実績を 1 件ずつ登録し、2 件目の入力で選択肢にその組織名が出ること、組織名を直すと両方の表示が変わることを確かめる。

**Acceptance Scenarios**:

1. **Given** 組織名を 1 つ登録してある, **When** オーナーが職歴または実績の組織名を入力し始める, **Then** 登録した組織名が選択肢に出る
2. **Given** 職歴と実績が同じ組織を指す, **When** オーナーが組織名を直す, **Then** 職歴と実績の両方で直した組織名が表示される
3. **Given** 組織名「作り物株式会社」が登録してある, **When** オーナーが同じ組織名で別の組織を作る, **Then** 作られない

---

### User Story 4 - スキルと経験年数を管理する (Priority: P2)

オーナーは実績に使ったスキルをつなぐ。スキルの経験年数は、そのスキルをつないだ実績の期間から自動で求まり、オーナーは手で上書きできる。

**Why this priority**: 経験年数を手で数えると、実績を足すたびにずれる。

**Independent Test**: 期間が重なる 2 件の実績に同じスキルをつなぎ、求めた経験年数が重なりを除いた長さから求めた値になることを確かめる。上書きした値を入れると、その値が使われることを確かめる。

**Acceptance Scenarios**:

1. **Given** 同じスキルをつないだ、期間が重なる 2 件の実績, **When** 経験年数を求める, **Then** 2 件の期間をつなぎ、重なりを除いた長さから求めた値になる
2. **Given** 経験年数を手で上書きしたスキル, **When** 経験年数を求める, **Then** 上書きした値になる
3. **Given** スキル「TypeScript」が登録してある, **When** オーナーが「typescript」を新しいスキルとして登録する, **Then** 登録されない
4. **Given** 職歴と、同じ組織で期間が重なる実績, **When** 職歴のスキルを求める, **Then** その実績につないだスキルが含まれる
5. **Given** 同じスキルをつないだ、サイトに載せる実績と載せない実績, **When** サイトで訪問者に出す経験年数を求める, **Then** サイトに載せる実績の期間だけから求めた値になる

---

### User Story 5 - 職歴と学歴を登録する (Priority: P3)

オーナーは職歴（組織・肩書・期間・本文・関連 URL・秘匿化するかどうか・サイトに載せるかどうか）と学歴（学校・学部・期間・備考）を登録・編集する。学歴は職務経歴書を通してだけ訪問者に出る。

**Why this priority**: 職歴と学歴は職務経歴書と一覧の材料であり、訪問者への表示はそれぞれの機能が持つ。

**Independent Test**: 職歴と学歴を 1 件ずつ登録・編集し、保存した値が管理画面で読めること、学歴が職務経歴書の外の訪問者への応答に含まれないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 職歴の登録の画面, **When** オーナーが終わりの日を空にして保存する, **Then** 所属が続いている職歴として保存される
2. **Given** 学歴が 1 件ある, **When** 訪問者が職務経歴書の外のページを見る, **Then** 学歴は応答に含まれない

---

### Edge Cases

- 終わりの日が始まりの日より前の職歴・実績・学歴は保存されない
- 日が分からない期間は、オーナーが便宜的な日を入れて保存する
- 終わりの日が空の実績は、続いている実績として扱う
- 職歴・実績が指している組織は削除できない
- 職務経歴書に写した職歴・実績を削除しても、作った職務経歴書の中身は残る
- 秘匿化した実績の代表画像は、訪問者に出さない
- 秘匿化した実績も個別のページを持つ。URL に出る識別子は既定の uid のままで、実際の題や組織名を含まない
- サイトに載せない職歴・実績は、秘匿化するかどうかに関わらず訪問者に出さない

## Requirements *(mandatory)*

### Functional Requirements

**組織**

- **FR-001**: オーナーは組織を、組織名と秘匿化した組織名を入れて登録できる。組織名は必須で、秘匿化した組織名は空にできる。秘匿化した職歴・実績が指す組織は、秘匿化した組織名を持たなければならず、持たない組織を指す職歴・実績は秘匿化できない
- **FR-002**: 職歴・実績の組織名の入力は、自由に入力でき、過去に入力した組織名を選択肢として出す
- **FR-003**: 同じ組織名の組織を 2 つ作れない
- **FR-004**: 組織名を直すと、その組織を指す職歴と実績の表示に反映する
- **FR-005**: 秘匿化した組織名は、組織ごとに 1 つだけ持つ
- **FR-006**: 職歴・実績が指している組織は削除できない
- **FR-041**: 個人開発と個人の活動の実績は、個人の組織 1 つに属する。個人の組織は、名前を変えても個人の組織として見分けられる

**職歴**

- **FR-007**: オーナーは職歴を、組織・肩書・始まりの日・終わりの日・本文・関連 URL・秘匿化するかどうか・サイトに載せるかどうかを入れて登録・編集・削除できる。終わりの日・本文・関連 URL は空にできる
- **FR-008**: 職歴の終わりの日が空なら、所属が続いている職歴として扱う
- **FR-009**: サイトに載せる職歴は、職務経歴書の外でも訪問者に見せる
- **FR-010**: 職歴は、既定で秘匿化する。オーナーが秘匿化しないと選んだ職歴だけを実際の値で出す

**実績**

- **FR-011**: オーナーは実績を、組織・種類・識別子・題・秘匿化した題・秘匿化するかどうか・サイトに載せるかどうか・代表画像・始まりの日・終わりの日・本文・関連 URL を入れて登録・編集・削除できる。代表画像・終わりの日・本文・関連 URL は空にできる
- **FR-012**: 実績の種類は、アプリ・登壇・イベント・その他のどれか 1 つである
- **FR-013**: 実績の識別子は 1〜100 文字の英小文字・数字・ハイフンで、ほかの実績と重ならない。登録したときの識別子は、題や組織名から推測できない uid である。オーナーは、秘匿化していない実績の識別子を書き換えられる。秘匿化した実績の識別子は uid から変えられない。秘匿化していない実績を秘匿化に切り替えると、識別子は新しい uid に戻る
- **FR-014**: 訪問者は、サイトに載せる実績の識別子を含む URL で、その実績の個別のページを開ける。サイトに載せない実績の URL には、実績が無いときと同じ応答を返す
- **FR-015**: 実績は、既定で秘匿化する。オーナーが秘匿化しないと選んだ実績だけを実際の値で出す
- **FR-016**: 実績は、組織とは別に参画先の会社名を持たない。参画先は本文に書く
- **FR-017**: 実績は職歴と直接つながらない。職歴ごとの実績は、職歴と同じ組織で、期間が重なる実績として求める
- **FR-018**: 実績の関連 URL は 1 件の実績に 1 つである

**サイトに載せるかどうか**

- **FR-044**: 職歴・実績は、サイトに載せるかどうかを 1 件ずつ持つ。既定はサイトに載せない。オーナーがサイトに載せると選んだ職歴・実績だけを訪問者に出す
- **FR-045**: サイトに載せない職歴・実績は、秘匿化するかどうかに関わらず、訪問者への応答（一覧と個別のページ）に含めない。管理画面と、限定公開用の職務経歴書を作るときにだけ使う
- **FR-046**: サイトに載せるかどうかと秘匿化するかどうかは、別の設定である。サイトに載せる職歴・実績を、実際の値で出すか秘匿化した値で出すかを、秘匿化するかどうかが決める

**秘匿化**

- **FR-019**: サイトに載せる、秘匿化した実績は、訪問者に秘匿化した題と、組織の秘匿化した組織名で出す
- **FR-020**: サイトに載せる、秘匿化した職歴は、訪問者に組織の秘匿化した組織名で出す
- **FR-021**: 秘匿化した職歴・実績の本文は、伏せた見た目で出し、本文の中身を訪問者への応答に含めない。本文の場所には「非公開」と出し、問い合わせの場所への導線を置く。導線は問い合わせの場所ができてから置く
- **FR-022**: 秘匿化した職歴・実績の実際の組織名と実際の題を、訪問者への応答に含めない
- **FR-023**: サイトに載せる、秘匿化しない職歴・実績は、訪問者に実際の値で出す
- **FR-024**: 本文の秘匿化した値は持たない
- **FR-026**: 秘匿化した職歴・実績で、訪問者に出してよい値は、FR-019・FR-020 が挙げる値と、期間・種類・肩書・使ったスキルだけである。関連 URL は訪問者への応答に含めない

**画像**

- **FR-027**: オーナーは職歴・実績の本文の中に画像とそのキャプションを置ける
- **FR-028**: オーナーは実績の代表画像を、その実績の本文に追加した画像から選べ、本文とは別に登録もできる。代表画像に選べるのは、その実績の画像だけである
- **FR-029**: 職歴は代表画像を持たない
- **FR-030**: 職歴・実績の画像（本文の画像と代表画像）は、秘匿化していない表示でだけ訪問者に出す。秘匿化した職歴・実績では画像を出さず、画像を訪問者への応答に含めない

**スキル**

- **FR-031**: オーナーはスキルを登録・編集・削除できる。大文字と小文字の違いだけの名前で、別のスキルを登録できない
- **FR-032**: オーナーは実績に、その実績で使ったスキルを 0 個以上つなげる。スキルをつなぐのは実績だけである
- **FR-033**: スキルの経験年数は、そのスキルをつないだ実績の期間をつなぎ、重なりを除いた長さから求める。求めた値は保存しない。経験年数は年と月で表す（例: 5 年 11 か月）。終わりの日が空の実績は、求める日までの期間として数える。経験年数は月を単位に、日付の日の部分を使わずに数え、各実績の始まりの月から終わりの月まで（終わりの日が空なら日本時間（Asia/Tokyo）の今月まで）を両端を含めて数え、期間が重なる月は 1 回だけ数える（例: 2020-04-01〜2022-03-31 は 24 か月で、2 年 0 か月）。サイトで訪問者に出す経験年数は、サイトに載せる実績だけから求める。管理画面の経験年数は、管理画面に載るすべての実績から求める
- **FR-034**: オーナーはスキルの経験年数を、年と月で手で上書きできる。上書きした値があれば、求めた値の代わりにその値を使う
- **FR-035**: 職歴のスキルは、職歴と同じ組織で期間が重なる実績につないだスキルを合わせて求める。サイトで訪問者に出す職歴のスキルは、サイトに載せる実績だけから求める

**学歴**

- **FR-036**: オーナーは学歴を、学校・学部・始まりの日・終わりの日・備考を入れて登録・編集・削除できる。学部・終わりの日・備考は空にできる
- **FR-037**: 学歴は職務経歴書を通してだけ訪問者に出し、学歴ごとに見せるかどうかの設定を持たない

**日付と書き換え**

- **FR-038**: 職歴・実績・学歴の始まりの日と終わりの日は年月日で持つ。日が分からないときは、オーナーが便宜的な日を入れる
- **FR-039**: 終わりの日は始まりの日より前にできない
- **FR-040**: 職歴・実績・学歴・組織・スキルを書き換えられるのはオーナーだけである。訪問者はこれらを書き換えられない
- **FR-042**: 職歴・実績を別の画面で先に書き換えていたら、あとから保存しようとした内容で上書きせずに保存を止め、手元の内容を残して知らせる
- **FR-043**: 登録したあとに秘匿化するかどうか、またはサイトに載せるかどうかを切り替えると、訪問者に見せる職歴・実績（一覧と個別のページ）は、切り替えた時点から新しい状態で出す。作った職務経歴書の中身は変えない

### Key Entities *(include if feature involves data)*

- **組織**: 組織名と秘匿化した組織名を持つ。職歴と実績が指す。個人開発は、自営業（個人）の組織 1 つで表す
- **職歴**: 組織・肩書・期間・本文・関連 URL・秘匿化するかどうか・サイトに載せるかどうかを持つ。実績と直接はつながらない
- **実績**: 組織・種類・識別子・題・秘匿化した題・秘匿化するかどうか・サイトに載せるかどうか・代表画像・期間・本文・関連 URL を持つ。スキルとつながる
- **学歴**: 学校・学部・期間・備考を持つ
- **スキル**: 名前と、手で上書きした経験年数を持つ。実績とつながる
- **画像**: 職歴・実績の本文の中から指される。持ち主は職歴か実績のどちらか 1 つ

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 秘匿化した職歴・実績について、訪問者が到達できるすべてのページの応答に、実際の組織名・実際の題・本文の中身・画像・関連 URL が 0 件含まれる
- **SC-002**: サイトに載せるすべての実績について、訪問者がその実績の URL で個別のページを開ける
- **SC-003**: 組織名を直したあと、その組織を指すすべての職歴と実績の次の表示で、直した組織名が出る
- **SC-004**: 期間の重なり方が異なる検査用の実績の組（重ならない・一部重なる・一方が他方を含む・終わりの日が空）のすべてで、求めた経験年数が手で計算した値と一致する
- **SC-005**: 学歴が、職務経歴書の外の訪問者への応答に 0 件含まれる
- **SC-006**: サイトに載せない職歴・実績のすべてについて、訪問者が到達できるすべてのページの応答に、その職歴・実績の題・秘匿化した題・組織名・本文の中身が 0 件含まれる

## Assumptions

**ほかの spec との関係**

- 職務経歴書の spec が、職歴・実績・学歴・スキルを写して職務経歴書を作る。組織名を直しても、作った職務経歴書の中身は変わらない。職務経歴書ごとに秘匿化した組織名を変えたいときは、その職務経歴書の中で直す
- 職歴・実績を物理削除するとき、それを写した職務経歴書の行は残す。残し方は職務経歴書の spec が持つ
- 一覧の spec が、職歴と実績を一覧に並べる。並べる日付・並び順・一覧での期間の見せ方は一覧の spec が持つ
- 画像を収める場所と、画像を配る仕組みは note の spec と共有する。この spec は職歴・実績が画像を使う要件だけを持つ
- 完全に削除できること（FR-11）、保存操作をせずに編集内容が保持されること（FR-14）、公開していない内容を範囲の外の人への応答に含めないこと（NFR-08）は [REQUIREMENTS.md](../../docs/REQUIREMENTS.md) が持つ

**データの入れ方**

- 組織の登録用の画面は、あってもなくてもよい。職歴・実績の入力の中で組織を作れれば足りる
- どの組織を実績の組織にするか（参画先と所属先が違う場合など）は、オーナーがデータを入力するときに判断する
- 「限定公開」という語はこの spec で使わない。職務経歴書にだけ使う

**決定が無く、この spec では決めない**

- スキルの表示順と、技術のまとまり（フロントエンド・バックエンドなど）
- 訪問者がスキルと経験年数を職務経歴書の外で見る場所
- 職歴ごとの実績と職歴のスキルを、訪問者にどこで見せるか
- 本文の書式
- 本文から消した画像の扱い
