## Clarifications

### Session 2026-11-10

- Q: 説明文が空の note では、ページの説明に何を出すか？ → A: オーナーが note ごとに、本文の最初の段落を説明に使うか、説明を出さないかを選ぶ。既定は本文の最初の段落を使う（2026-11-10、オーナー。[issue #219 のコメント](https://github.com/ksyunnnn/synsk.me/issues/219#issuecomment-6766542397)）。選ぶ値は版でなく note に持ち、選び直しても版を足さない（2026-11-10、作業者。research.md の R19）
- Q: 代表画像に、題を入れて自動で作る画像を持つか？ → A: 持たない。synsk.me はメディアのサイトではないため。代表画像は、その note の画像と note 用のサイト共通の 400×400 の画像のどちらかで、選ばなければ後者である。大きな画像を強制する SNS が現れたら、そのときに自動で作ることを検討する（2026-11-10、オーナー。[issue #219 の U8 の報告](https://github.com/ksyunnnn/synsk.me/issues/219#issuecomment-6766846712)）
- Q: note の URL が他のサービスに貼られたとき、カードはどの形か？ → A: 大きな画像のカードではなく、小さい画像の隣に文字が並ぶカードにする。代表画像がその note の画像なら、その画像を縮めずに使う。代表画像を選ばない note は、note 用のサイト共通の 400×400 の画像を使う。その画像はオーナーが用意し、用意するまではカードに画像を付けない。仮の画像は置かない（索引されるのを避けるため）。サイト共通の 1200×630 の画像とサイト全体のカードの形は変えない（2026-11-10、オーナー。[issue #219 の U8 の報告](https://github.com/ksyunnnn/synsk.me/issues/219#issuecomment-6766846712)）

## Terms

- **オーナー**、**訪問者**: [001 の spec](../001-career-and-project/spec.md) の Terms と同じ意味で使う
- **note**: synsk.me が持つ記事（[ADR-0023](../../docs/decisions/0023-note-naming.md)）
- **版**: note の題・説明文・本文の組。オーナーが保存するたびに 1 つ増え、増えた版は書き換えない。最も新しい版が、オーナーが書き換えている内容である
- **本文**: note の版が持つ文章。画像の印と、参照先の URL を中に置く
- **下書き**: 訪問者に見せない note の状態。作った note は下書きである
- **公開**: 訪問者に見せる note の状態。公開した note は、公開した版の内容を訪問者に見せる
- **公開した版**: 最後に公開したときの版。公開した後に保存した版は、公開し直すまで訪問者に見えない
- **識別子**: note を訪問者の URL で指す文字列（slug）
- **削除**: 管理画面から note を消す操作。note に削除済みの印を付けるだけで、データは残し、訪問者に出さない。オーナーは削除した note を元に戻せる
- **完全に消す**: note と、その note の版・画像・転載先のデータを残さず消すこと
- **代表画像**: note のページの URL が他のサービスに貼られたときのカードに出す画像（[CRAWLING.md](../../docs/CRAWLING.md) の「リンクが貼られたときの見え方」）
- **URL カード**: 本文に書いた参照先の URL を、参照先の題と画像を添えて見せる表示
- **転載先**: note を外部のサービスに複製した先の URL（[ADR-0006](../../docs/decisions/0006-posse-publishing-strategy.md) の POSSE）

## Clarifications

### Session 2026-11-10

- Q: 参照先の情報は、いつ取るか？ → A: オーナーが見た目の確認の画面（`/dash/notes/{uid}/preview`）を開いたときに、参照先の情報を持たない URL だけを取る。定期実行で取り直さない。訪問者の表示では取らない（オーナーの決定）
- Q: 本文から消えた URL の参照先の情報は、どう扱うか？ → A: 消さずに残す（オーナーの決定）
- Q: 参照先の情報が取れなかった URL は、訪問者にどう見せるか？ → A: URL の文字列のリンクで出す（オーナーの決定）
- Q: 一度取った参照先の情報は、どう取り直すか？ → A: オーナーが見た目の確認の画面で、URL カードごとに置いた「取り直す」を押すと、その URL の題と画像を取り直して書き換える。取れなければ前の情報を残し、そのカードのそばに取れなかった理由を出す。オーナーだけが使える（2026-11-10、オーナー）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - note を書いて公開し、訪問者に読ませる (Priority: P1)

オーナーは管理画面で note を作り、識別子・題・説明文・本文を入れて保存する。保存した note は下書きで、オーナーが公開すると、訪問者は識別子を含む URL でその note を読める。公開した後に直した内容は、公開し直すと訪問者に見える。

**Why this priority**: note を書いて公開できなければ、この機能のほかの部分は使い道がない。

**Independent Test**: note を 1 件作って保存し、公開する。訪問者としてその URL を開き、保存した題・説明文・本文が表示されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 下書きの note, **When** 訪問者がその note の URL を開く, **Then** note の内容は表示されず、応答に含まれない
2. **Given** 題が空の版を持つ下書きの note, **When** オーナーが公開する, **Then** 公開されず、題を入れるよう示される
3. **Given** 題を入れた下書きの note, **When** オーナーが公開する, **Then** 訪問者がその note の URL で題・説明文・本文を読める
4. **Given** 公開した note, **When** オーナーが本文を直して保存し、公開し直さない, **Then** 訪問者には直す前の本文が表示される
5. **Given** 公開した note を直して保存した, **When** オーナーが公開し直す, **Then** 訪問者に直した本文が表示され、初めて公開した日時は変わらない
6. **Given** 公開した note, **When** オーナーが識別子を変えようとする, **Then** 変えられない

---

### User Story 2 - 公開をやめる・削除する・削除を戻す (Priority: P1)

オーナーは公開した note を下書きに戻せる。不要になった note は削除でき、削除した note は元に戻せる。下書きに戻した note と削除した note は、訪問者に見えない。

**Why this priority**: 一度出した内容を引っ込められないと、誤って公開した内容が訪問者に出続ける。

**Independent Test**: 公開した note を下書きに戻し、訪問者への応答に内容が含まれないことを確かめる。別の note を削除し、訪問者への応答に内容が含まれないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 公開した note, **When** オーナーが下書きに戻す, **Then** 訪問者への応答にその note の内容が含まれない
2. **Given** 下書きに戻した note, **When** オーナーが公開し直す, **Then** 初めて公開した日時は下書きに戻す前と同じである
3. **Given** note を 1 件削除した, **When** 訪問者がその note の URL を開く, **Then** note の内容は応答に含まれない
4. **Given** 識別子「sample-note」（作り物）の note を削除した, **When** オーナーが同じ識別子で別の note を作る, **Then** 作られない
5. **Given** 公開した note を削除した, **When** オーナーがその note を元に戻す, **Then** note は公開に戻り、削除前と同じ版を訪問者が読める
6. **Given** 下書きの note を削除した, **When** オーナーがその note を元に戻す, **Then** note は下書きに戻り、削除前の版を持つ

---

### User Story 3 - 過去の版を残し、戻す (Priority: P2)

オーナーが保存するたびに版が 1 つ増え、前の版は書き換えられずに残る。オーナーは過去の版を見て、その版に戻せる。

**Why this priority**: 書き直して悪くなったときに、前の内容を取り戻せないと書き直すことをためらう。

**Independent Test**: note を 3 回保存し、3 つの版がそれぞれ保存したときの内容のまま読めることを確かめる。1 つ目の版に戻し、戻した内容になることを確かめる。

**Acceptance Scenarios**:

1. **Given** 3 回保存した note, **When** オーナーが版の一覧を見る, **Then** 3 つの版が、それぞれ保存したときの題・説明文・本文のまま読める
2. **Given** 3 つの版を持つ note, **When** オーナーが 1 つ目の版に戻す, **Then** 1 つ目の版の題・説明文・本文が 4 つ目の版として保存され、3 つの版は残る
3. **Given** 公開した note, **When** オーナーが過去の版に戻し、公開し直さない, **Then** 訪問者には戻す前に公開していた版が表示される

---

### User Story 4 - 書いている内容を失わない (Priority: P2)

オーナーが書いている内容は、保存の操作をしなくても、書いている端末に残る。同じ note を別の画面でも開いていて、そちらで先に保存した場合、あとから保存しようとした画面の保存は止まり、その画面で書いた内容は残る。

**Why this priority**: 書いた内容が消えると、書き直す手間がかかり、書くこと自体を避けるようになる。

**Independent Test**: 同じ note を 2 つの画面で開き、片方で保存したあと、もう片方で保存する。2 つ目の保存が止まり、知らせが出て、2 つ目の画面の内容が残ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 本文を書きかけて保存していない, **When** オーナーが同じ端末で編集の画面を開き直す, **Then** 書きかけの内容が残っている
2. **Given** 本文を書きかけて保存していない, **When** オーナーが別の端末で同じ note を開く, **Then** 書きかけの内容は表示されず、最後に保存した版の内容が表示される
3. **Given** 同じ note を画面 A と画面 B で開いた, **When** 画面 A で保存したあと、画面 B で保存する, **Then** 画面 B の保存は止まり、オーナーに知らされ、画面 B で書いた内容は画面 B に残る
4. **Given** 画面 A で note を開いた, **When** 画面 A で続けて 2 回保存する, **Then** 2 回とも保存される

---

### User Story 5 - 本文に画像を置き、代表画像を選ぶ (Priority: P2)

オーナーは note の本文の中に画像を置ける。代表画像は、その note の画像と note 用のサイト共通の 400×400 の画像から選ぶ。

**Why this priority**: 画像を貼る手間が、書かなくなる理由の 1 つに挙がっている（[ADR-0014](../../docs/decisions/0014-authoring-and-datastore.md)）。

**Independent Test**: 本文に画像を 1 枚置いて公開し、訪問者に画像が表示されることを確かめる。代表画像をその画像にし、他のサービスに貼られたときのカードにその画像が出ることを確かめる。

**Acceptance Scenarios**:

1. **Given** 本文に画像を置いた公開の note, **When** 訪問者がその note を開く, **Then** 画像が表示される
2. **Given** 代表画像を選んでいない note, **When** その note の URL が他のサービスに貼られる, **Then** 小さい画像の隣に文字が並ぶカードが出る。画像は note 用のサイト共通の 400×400 の画像で、オーナーが用意するまでは画像の無いカードになる
3. **Given** note A と note B がある, **When** オーナーが note A の代表画像に note B の画像を選ぼうとする, **Then** 選べない
4. **Given** 本文に画像を置いた下書きの note, **When** 訪問者がその画像を取りに行く, **Then** 画像は返らない
5. **Given** 公開した note に、公開した後に保存した版でだけ本文に画像を置いた, **When** 訪問者がその画像の URL を開く, **Then** 公開し直すまで画像は返らない

---

### User Story 6 - 参照先の URL をカードで見せる (Priority: P3)

オーナーが本文に参照先の URL を書くと、訪問者には参照先の題と画像を添えたカードで表示される。

**Why this priority**: 参照先の URL だけでは、訪問者が開く前に中身を推し量れない。ただし、無くても note は読める。

**Independent Test**: 本文に参照先の URL を書いた note を公開し、訪問者にその URL が参照先の題を添えたカードで表示されることを確かめる。表示のたびに参照先へ取りに行かないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 本文に参照先の URL を書いた公開の note, **When** 訪問者がその note を開く, **Then** 参照先の題と画像を添えたカードが表示される
2. **Given** 参照先の情報を一度取った URL, **When** 訪問者がその note を何度開いても, **Then** そのたびに参照先へ取りに行かない
3. **Given** 2 つの note が同じ参照先の URL を書いている, **When** オーナーが片方の note の見た目の確認の画面で、その URL のカードの「取り直す」を押す, **Then** 2 つの note のカードがどちらも取り直した中身になる
4. **Given** 参照先の情報を一度取った URL, **When** オーナーが「取り直す」を押し、参照先の情報が取れない, **Then** カードは前の情報のまま出て、そのカードのそばに取れなかった理由が出る

---

### User Story 7 - 転載先を記録する (Priority: P3)

オーナーは note を外部のサービスに転載したとき、その転載先の URL を note に記録する。

**Why this priority**: 転載先を記録しないと、外部から取り込んだ同じ内容が一覧に重なって並ぶ（[ADR-0006](../../docs/decisions/0006-posse-publishing-strategy.md)）。

**Independent Test**: note に転載先の URL を 1 つ記録し、同じ URL を別の note に記録できないことを確かめる。

**Acceptance Scenarios**:

1. **Given** note が 1 件ある, **When** オーナーが転載先の URL を 2 つ記録する, **Then** 2 つとも記録される
2. **Given** note A に記録した転載先の URL, **When** オーナーが同じ URL を note B に記録する, **Then** 記録されない

---

### Edge Cases

- 下書きのうちは題が空でも保存できる。題が空の版は公開できない
- 下書きの note の識別子は、初めて公開するまで変えられる
- 公開した note を下書きに戻しても、公開した版と初めて公開した日時は残る
- 削除した note の識別子は、別の note に使えない。このため、削除した note を元に戻すときに識別子がほかの note と重なることは起きない
- 代表画像に選んだ画像は、その note の画像に限る
- 公開した後に保存した版にだけ置いた画像は、公開し直すまで、画像の URL を知っている訪問者にも出さない
- 書きかけの内容を残した端末で、別の画面から先に保存された note を開いたときも、書きかけの内容は消さない
- 参照先の情報が取れない URL を書いた note も保存でき、公開できる

## Requirements *(mandatory)*

### Functional Requirements

**作成と識別子**

- **FR-001**: オーナーは管理画面で note を作れる。作った note は下書きである
- **FR-002**: note の識別子は 1〜100 文字の英小文字・数字・ハイフンで、ほかの note と重ならない。削除した note の識別子とも重ならない
- **FR-003**: オーナーは、一度も公開していない note の識別子を変えられる。一度でも公開した note の識別子は変えられない
- **FR-004**: 訪問者は、識別子を含む URL で、公開の note のページを開ける。訪問者の URL には識別子を出し、note の連番の番号は出さない

**版と保存**

- **FR-005**: 版は題・説明文・本文を持つ。説明文は空にできる。題は 200 文字まで、本文は 100,000 文字までである
- **FR-006**: オーナーが保存するたびに、note に版が 1 つ増える。増えた版は書き換えない
- **FR-007**: オーナーが書き換える内容は、その note の最も新しい版から始まる
- **FR-008**: オーナーは note の過去の版を、保存したときの題・説明文・本文のまま読める
- **FR-009**: オーナーは note を過去の版に戻せる。戻すと、戻した版の題・説明文・本文が新しい版として保存される。訪問者には、オーナーが公開し直すまで、それまで公開していた版を見せる

**公開と下書き**

- **FR-010**: note の状態は下書きか公開のどちらかである
- **FR-011**: オーナーは note を公開できる。公開すると、その時点の最も新しい版が公開した版になる。題が空の版は公開できない
- **FR-012**: 訪問者に見せる題・説明文・本文は、公開した版のものである。公開した後に保存した版は、公開し直すまで訪問者への応答に含めない
- **FR-013**: note は初めて公開した日時を持つ。公開し直しても、下書きに戻しても、この日時は変わらない
- **FR-014**: オーナーは公開の note を下書きに戻せる。下書きに戻した note の内容は訪問者への応答に含めない。下書きに戻しても公開した版は残る
- **FR-015**: 下書きの note の内容は、訪問者への応答に含めない

**削除**

- **FR-016**: オーナーは管理画面から note を削除できる。削除は note に削除済みの印を付けるだけで、データを残し、訪問者への応答に含めない。オーナーは削除した note を元に戻せる。戻すと、note は削除前の状態（下書きか公開か）と版に戻る
- **FR-017**: note を完全に消すときは、その note の画像・転載先・版と note を一緒に消し、一部だけが残る状態にしない。参照先の URL の情報は、note を完全に消しても消さない

**同時編集と編集中の内容**

- **FR-018**: 書きかけの内容は、保存の操作をしなくても、書いている端末に残る。書きかけの内容は、オーナーが保存するまで保管するデータに書かない
- **FR-019**: 別の端末で続きを書くには、オーナーが保存する。保存していない書きかけの内容は、別の端末に出ない
- **FR-020**: オーナーが保存するとき、その note の最も新しい版が、その画面で編集を始めたときの最も新しい版と違えば、保存を止める。止めたときは、その画面の内容を残し、オーナーに知らせる
- **FR-021**: 保存できた画面では、保存した版を、次に保存するときに比べる版とする
- **FR-022**: オーナーはスマートフォンから note を作成・編集・公開できる

**画像**

- **FR-023**: オーナーは note の本文の中に画像を置ける。本文に置いた画像は、その note の画像として持つ
- **FR-024**: note の代表画像は、その note の画像と note 用のサイト共通の 400×400 の画像のどちらか 1 つである。オーナーが選ばなければ、note 用のサイト共通の 400×400 の画像である。note の URL が他のサービスに貼られたときは、小さい画像の隣に文字が並ぶカードにする。その note の画像は縮めずに使う
- **FR-025**: オーナーは代表画像に使う画像を、その note の本文に置いた画像から選べ、本文とは別に登録もできる。代表画像に選べるのは、その note の画像だけである
- **FR-026**: note の画像は、その note が公開で、削除していないときだけ訪問者に出す。訪問者に出すのは、公開した版の本文に置いた画像と、その note の代表画像だけである。公開した後に保存した版にだけ置いた画像は、公開し直すまで、画像の URL を知っていても訪問者に出さない。画像の置き場を訪問者に直接開かず、サイトを通して出す

**URL カード**

- **FR-027**: 本文に書いた参照先の URL は、参照先から取った題と画像を添えたカードで訪問者に見せる。参照先の情報が取れなかった URL は、URL の文字列のリンクで見せる
- **FR-028**: 参照先から取った情報は保存し、訪問者が表示するたびに参照先へ取りに行かない。参照先の情報は、オーナーが見た目の確認の画面を開いたときに、参照先の情報を持たない URL だけを取る。オーナーは見た目の確認の画面で、URL カードごとに参照先の情報を取り直せる。定期実行で取り直さない
- **FR-029**: 参照先から取った情報は、版の外に URL ごとに 1 つ持つ。版には URL だけを残す。参照先の情報を取り直すと、その URL を書いたすべての note のカードが取り直した中身になる。取り直せなければ前の情報を残し、取れなかった理由をオーナーに示す。本文から消えた URL の参照先の情報は消さずに残す
- **FR-030**: カードの画像は、参照先の画像の URL だけを持ち、画像そのものは保管しない

**転載先**

- **FR-031**: オーナーは note ごとに、転載先の URL を 0 個以上記録できる
- **FR-032**: 同じ転載先の URL を、2 つ以上記録できない。別の note にも記録できない

**書き換え**

- **FR-033**: note・版・画像・転載先を書き換えられるのはオーナーだけである。訪問者はこれらを書き換えられない

**説明**

- **FR-034**: オーナーは note ごとに、説明文が空のときに、本文の最初の段落を説明に使うか、説明を出さないかを選べる。オーナーが選ばなければ、本文の最初の段落を使う。説明文が空でない版では、選んだ値にかかわらず説明文を説明に使う

### Key Entities *(include if feature involves data)*

- **note**: 識別子・状態・公開した版・初めて公開した日時・削除したかどうか・代表画像の出どころ・説明文が空のときに本文の最初の段落を使うかを持つ。版・画像・転載先を持つ
- **版**: 題・説明文・本文と、保存した日時を持つ。1 つの note に属し、書き換えない
- **画像**: note の本文と代表画像から指される。画像の記録は、職歴・実績・life event の画像と同じ仕組みに持ち、持ち主は 1 つだけである
- **参照先の情報**: 参照先の URL・題・画像の URL・取った日時を持つ。URL ごとに 1 つで、note には属さない
- **転載先**: 転載先の URL を持つ。1 つの note に属する

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 下書きの note・削除した note・公開した後に保存して公開し直していない版・公開した版の本文に無く代表画像でもない画像について、訪問者が到達できるすべての応答に、その内容が 0 件含まれる
- **SC-002**: 2 つの画面から同じ note を保存する検査のすべてで、先に保存した版の内容が後の保存で失われた件数が 0 件、止めた保存の画面で内容が失われた件数が 0 件である
- **SC-003**: 保存したすべての版が、保存したときの題・説明文・本文と 1 文字も違わずに読める
- **SC-004**: 一度公開した note のすべてで、その後の保存・公開し直し・下書きに戻す操作のあとも、訪問者の URL と初めて公開した日時が変わらない
- **SC-005**: URL カードを含む note を訪問者が表示したとき、参照先へ取りに行く回数が 0 回である
- **SC-006**: オーナーがスマートフォンだけで、note を作り、保存し、公開するまでを終えられる
- **SC-007**: 削除して元に戻したすべての note が、削除前と同じ状態（下書きか公開か）・版・識別子を持つ

## Assumptions

**ほかの spec・文書との関係**

- 一覧の spec が、公開の note を一覧に並べる。一覧で note を並べる日付は作成日とする（2026-11-04 のオーナーの回答）。並べ方の詳細は一覧の spec が持つ
- 転載先の URL と一致する外部の activity を一覧から除くことは、一覧の spec が持つ
- 画像を収める仕組みは、職歴と実績・外部 activity の取得の spec と共有する。職歴・実績・life event の画像の要件は、それぞれの spec が持つ
- 完全に削除できること（FR-11）、公開されたときの見た目を公開前に確認できること（FR-13）、保存操作をせずに編集内容が保持されること（FR-14）、公開していない内容を範囲の外の人への応答に含めないこと（NFR-08）、キャッシュに残さないこと（NFR-09）は [REQUIREMENTS.md](../../docs/REQUIREMENTS.md) が持つ
- 他のサービスに URL が貼られたときのカードの題・説明・画像の出し方は [CRAWLING.md](../../docs/CRAWLING.md) が持つ。説明文が空の note の説明は FR-034 に従う
- 管理画面は `/dash/` 配下に置く（[ADR-0016](../../docs/decisions/0016-url-conventions.md)）。オーナーであることは、アプリケーションの外で Cloudflare Access が判定する（[ADR-0013](../../docs/decisions/0013-access-authentication.md)）

**決まっていて、実装のときに詰めるもの**

- 本文の書式は暫定で Markdown とし、note を実装するときに調整する
- 版が増えたときの扱いは、データの大きさを測る手順を用意し、閾値を割ってから決める
- 完全に消す画面は、この spec の範囲に入れない。オーナーは作る見込みを示している
- 同時編集で比べるのは版だけで、そのための値を足さない

**決定が無く、この spec では決めない**

- 識別子の候補を題から示すかどうか（材料: ADR-0016）
- 訪問者の note の URL の形（材料: ADR-0016）
- 削除した note の URL を訪問者が開いたときの応答
- 公開の操作でも、保存と同じく編集を始めたときの版と比べるか
- 保存を止めたあと、オーナーが内容を合わせる手順
- 公開の操作のあと、訪問者に見えるまでの時機とキャッシュの扱い
- 本文のどの URL をカードにするか
- カードの画像の出し方
- note の更新日（初めて公開した日とは別の日付）をどこに持つか
- 本文から消した画像のデータを残すかどうか、画像の形式と大きさの上限
- 転載先の URL を訪問者に見せるかどうか
- 画像の置き場と保管するデータのずれの扱い
