# Policy

> 機械の読み手にどう応えるかを書く。理由と実装方法は書かない。

根拠: [ADR-0024](./decisions/0024-machine-readers.md)

---

## 取得を許す相手

- 公開しているコンテンツの取得と引用を、目的を問わず許す。目的は学習、検索インデックス、利用者の代理による取得、エージェントの操作を含む
- `robots.txt` は許可を示すために書き、取得の遮断には使わない
- なりすましと、量や頻度が度を越したアクセスは Cloudflare の層で止める。相手が名乗りどおりかの判定は、Cloudflare の検証済みボットに委ねる

## 取らせないもの

- 非公開と限定公開のコンテンツを `robots.txt` で守らない
- 限定公開は、推測しにくい URL を知る人に開く。URL には期限などを設け、流出と利用者の代理による取得に備える
- 限定公開の URL を `sitemap.xml`、フィード、`llms.txt` に載せない
- 配信する値は、許可リスト方式（出してよい値だけを列挙する）で選ぶ

## 差し出し方

- `sitemap.xml` に、公開しているページを載せる
- note を Atom フィードで配信する
- `llms.txt` を置き、各ページを HTML の URL で示す
- Markdown 版のページと API は用意しない
- AI の読み手のために構造化データを足さない

## リンクが貼られたときの見え方

SNS やチャットなど、他のサービスに URL が貼られたときに表示されるカードの扱い。

- カード画像は note ごとに次から選ぶ。選ばなかった note は1になる
  1. 題を入れた画像を自動で作る
  2. note に追加した画像を使う
  3. サイト共通のアイキャッチを使う
- 限定公開のページのカードは、題・説明・画像に中身を出さず、汎用の表示にする

## 取得の後の利用

- 学習、AI の回答への投入、検索のいずれにも使ってよいと、`robots.txt` で明示する
- 使うときは出典とリンクを示してほしいと要望する

## 取得の負荷

- 公開しているページ、フィード、`sitemap.xml`、カード画像は、エッジのキャッシュから返す。公開または修正したときに、該当するキャッシュを消す
- カード画像は一度作ったものを使い回し、取得のたびには作らない
- レート制限ルールを1本置き、キャッシュをすり抜ける度を越した量のアクセスを止める
- Bot Fight Mode を有効にしない
- 取得の量は、Workers のエラー数と AI Crawl Control で見る
